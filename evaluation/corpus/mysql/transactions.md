# MySQL 事务

## MVCC 一致性读取

InnoDB 的普通 `SELECT` 通常属于快照读。事务通过 Read View 判断某个行版本对当前查询是否可见，而不是每次都读取其他事务刚刚提交的最新值。隔离级别不同会影响 Read View 的创建与复用时机，例如可重复读事务通常复用首次快照读建立的一致性视图。

行记录包含用于版本判断的隐藏事务信息。数据被更新时，旧版本可以通过 undo log 形成的版本链读取；查询按照 Read View 的可见性规则在版本链上找到当前事务能够看到的版本。这样，读操作通常不需要为了获得一致视图而阻塞正在修改相同行的事务。

## 快照读与当前读

`SELECT ... FOR UPDATE`、`UPDATE` 和 `DELETE` 等需要操作当前记录的语句属于当前读，会读取最新可用版本并配合锁保证并发修改安全。MVCC 主要解决一致性快照读取，不意味着事务中的所有 SQL 都不加锁，也不能脱离隔离级别讨论可见性。
