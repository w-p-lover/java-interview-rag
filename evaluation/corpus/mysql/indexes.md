# MySQL 索引

## 联合索引与最左前缀

联合索引按照定义时的列顺序组织索引键。查询条件从联合索引的最左列开始连续匹配时，通常更容易利用该索引缩小扫描范围；跳过前导列或在中间列使用无法继续确定范围的条件，往往不能充分利用后续列完成定位。

是否使用索引最终由优化器结合选择性、统计信息和成本决定，不能只根据 SQL 中出现了索引列就断言一定命中。排查时应查看执行计划中的访问类型、实际使用索引和扫描行数。

## 覆盖索引与回表

二级索引叶子节点保存索引列和主键值。当查询所需列都能从索引中取得时，可以形成覆盖索引，减少根据主键回到聚簇索引读取完整记录的次数。覆盖索引能降低部分随机 IO，但不应为了覆盖所有查询而无限增加宽索引。
