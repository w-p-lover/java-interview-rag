# JVM 内存管理

## GC Roots 与可达性分析

JVM 判断对象是否仍然存活时，会从一组称为 GC Roots 的根节点开始遍历对象引用图。能够从任意 GC Root 沿引用链到达的对象被认为可达，本轮垃圾回收不会把它当作普通垃圾直接回收；无法从根节点到达的对象才会进入后续回收判定。

常见 GC Roots 包括虚拟机栈中栈帧局部变量表引用的对象、类静态字段引用的对象、运行时常量池引用的对象、JNI 本地引用以及 JVM 内部持有的必要对象。可达性分析关注当前引用关系，而不是简单统计对象被引用的次数，因此能够识别相互引用但整体已经不可达的对象环。

## 回收判定边界

“不可达”表示对象具备被回收的条件，不等于它一定会在发现后立即释放。具体收集时机、引用类型处理和终结机制由垃圾收集器与 JVM 规则共同决定。面试中应把 GC Roots、引用链和不可达判定讲清楚，不把它简化成引用计数算法。
