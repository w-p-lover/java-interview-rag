# Java 集合

## HashMap 的查询过程

`HashMap` 根据 key 的哈希值定位数组桶，再在桶内比较 key。哈希分布较均匀时，每个桶中的元素数量很少，所以常见的平均查询复杂度是 `O(1)`。大量哈希冲突会增加桶内查找成本，因此合理的 `hashCode` 实现和扩容都很重要。

## 链表树化条件

Java 8 中，冲突桶开始使用链表保存节点。当桶内节点数量达到树化阈值 8，并且当前数组容量至少为 64 时，该桶可以转换为红黑树。若数组容量还小于 64，`HashMap` 会优先扩容，而不是立即树化，以便通过重新分布减少冲突。红黑树用于限制严重冲突下的查找退化，但不改变通常所说的平均 `O(1)` 查询复杂度。

## 扩容与负载因子

默认负载因子为 0.75。元素数量超过容量与负载因子的乘积时会触发扩容，节点根据原哈希位置重新分布到新数组。扩容本身有成本，因此初始化容量应结合预估数据量选择，但不应仅为了避免一次扩容而设置极大的数组。
