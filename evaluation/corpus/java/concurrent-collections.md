# Java 并发集合

## ConcurrentHashMap 的并发控制

普通 `HashMap` 不提供并发安全，多线程同时修改可能产生覆盖、状态不一致或不可预期的读取结果。并发读写映射通常优先考虑 `ConcurrentHashMap`，而不是在整个普通 Map 外统一加一把粗粒度锁。

Java 8 的 `ConcurrentHashMap` 结合 CAS、桶级同步和可见性保证处理并发更新，避免所有操作竞争同一把全局锁。读取通常不需要锁住整个容器，更新冲突也尽量限制在相关桶上，从而在保证线程安全的同时降低竞争。

## 复合操作边界

线程安全容器不代表多步业务逻辑天然原子。先读取再判断、随后写入的复合流程应优先使用 `putIfAbsent`、`compute`、`merge` 等原子 API，或在更高层明确同步边界。选择并发容器时既要看单次方法是否安全，也要看完整业务操作是否需要原子性。
