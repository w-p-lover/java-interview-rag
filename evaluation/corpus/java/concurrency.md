# Java 并发

## ThreadPoolExecutor 接收任务

调用 `execute` 提交新任务时，线程池先检查当前工作线程数。少于 `corePoolSize` 时，优先创建核心线程执行任务，即使已有核心线程处于空闲状态。核心线程数已满后，线程池尝试把任务放入工作队列。

任务成功入队后还会重新检查线程池运行状态，避免关闭过程留下无法处理的任务。如果队列已满，线程池会在工作线程数小于 `maximumPoolSize` 时创建非核心线程处理任务；达到最大线程数后，执行配置的 `RejectedExecutionHandler` 拒绝策略。常见策略包括抛出异常、由提交线程执行、丢弃当前任务或丢弃队列中最旧任务。

## volatile 的可见性与有序性

对 `volatile` 变量的写入对随后读取该变量的线程可见，并且 Java 内存模型会在相关读写处建立有序性约束，禁止破坏该语义的特定指令重排序。它适合状态标记或发布已经构造好的数据，但不能替代所有同步手段。

`count++` 不是一次不可分割的操作，而是读取旧值、计算新值、写回结果等多个步骤。多个线程即使读写的是 `volatile` 变量，也可能读取到相同旧值并发生覆盖，所以 `volatile` 不能保证自增的原子性。并发计数应使用 `AtomicInteger` 等原子类，或使用锁保护复合操作。
