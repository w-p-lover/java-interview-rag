# 后续开发路线

> 更新时间：2026-08-28。用于约束投递前冲刺和投递后的技术扩展，不记录开发流水账。

## 当前判断

项目的知识库、RAG、文本面试、证据化评分、复习 attempt 和受控 Tool Calling 已形成基础闭环。现阶段不再平均扩展功能，而是进入“投递前冲刺”：少数方向完整实现并验证，少数前沿方向只做隔离 POC，其余方向保留进入条件，不在主链路留下半成品。

开发状态只有三种：

1. **实现并验证**：进入主业务，有代码、固定样本、运行结果和失败边界，可以写入简历成果。
2. **独立 POC**：只验证技术可行性，不影响主业务，简历和面试中必须明确表述为 POC。
3. **后续方向**：只有设计、进入条件和不采用理由，不写成已经掌握或已经实现。

## 执行原则

- 每轮只完成一个可验证闭环，投递价值和可讲深度优先于功能数量。
- 先建立简单方案和固定基线，再增加检索、Agent 或图工作流复杂度；没有收益就停止扩张。
- Java/Spring AI 继续作为主业务与 Agent 开发平台，DashScope 提供模型，MySQL/Qdrant 保存业务事实与知识资料。
- Codex 可以承担主要实现，但每个闭环必须留下调用链、技术取舍、指标、失败场景和面试追问材料。
- 简历和 JD 默认不持久化，不把模型推断包装成用户事实，不从模型自然语言直接生成写操作。
- 没有完成固定验证的技术只能写“调研”或“POC”，不能进入简历核心成果。

## 一、现在开发：投递前必须收口

### 1. RAG 查询拆分真实对照

当前查询拆分 + RRF 对照代码已经完成，但真实对照显示排序退化，因此不接入生产检索。

开发内容：

- 在费用授权上下文明确时运行固定 20 题真实对照。
- 比较基线与候选的 Hit@1、Recall@5、MRR、标题路径召回和无答案拒答准确率。
- 记录拆分题数、额外查询次数、耗时和失败题，不只记录总分。
- 只有多证据召回改善、排序和拒答不退化时，才评估接入生产；否则保留实验结论并停止扩张。

涉及技术：确定性查询规划、Multi-query Retrieval、Reciprocal Rank Fusion、Qdrant、Embedding、离线评估。

完成结果：已产生 `2026-08-27-rag-query-decomposition-comparison.json`。候选 Hit@1 `0.9412`、MRR `0.9706`，低于原查询的 `1.0000`；明确不采用。

### 1.1 同来源相邻 Chunk 上下文扩展

状态：已实现并完成确定性回归，尚未证明固定集指标提升。

- 初始向量检索命中后，按同一来源、同一文档版本和相邻 `chunk_order` 补充前后一段资料。
- 每次最多处理 3 个种子、最终最多 8 条资料；按来源/版本/顺序去重，初始无命中时不扩展。
- 只接入 RAG 回答上下文，裸检索、查询评估和面试知识绑定继续使用原始 topK/阈值语义。
- 后续验证只比较标题路径召回、回答要点覆盖、拒答准确率和额外 Embedding 调用次数；若无净收益则保留实现或回退，不继续增加父子索引/GraphRAG。

### 1.2 PDF 知识资料上传与页面级结构化入库

状态：上传、页面/章节结构化 Chunk 与独立结构检索评估代码均已实现；真实结构检索基线待新的 Embedding 费用授权。

- 上传接口和资料准备页支持 `.pdf`，返回页数、OCR 候选页和版面解析告警。
- PDF 优先识别真实标题、正文、列表、代码、表格和跨页章节，无标题时才按页回退；Qdrant、检索与回答上下文保留页码和块类型。
- 独立 3 题合成 PDF 结构集覆盖代码、表格和跨页正文，报告统计标题路径、页码、块类型与完整结构召回；不改变生产检索排序，也不加入 20 题 Chat 回答评估。
- 下一步只运行一次授权 `text-embedding-v3` 结构基线；只有固定问题证明结构字段不足，才评估块类型权重或章节聚合。当前不自动 OCR，不直接进入轻量文档结构图。

### 2. 简历证据审计官基线

这是投递前最重要的新功能。第一版使用普通 Spring AI 编排，不提前依赖图框架。

开发内容：

- 复用现有简历文本输入，结构化提取项目、技术、职责、时间和结果等事实。
- 每个事实携带简历中的逐字证据，由 Java 服务端执行字面包含校验。
- 输出严格区分已确认事实、信息缺失、风险判断和表达建议。
- 固定样本覆盖完整简历、缺少量化结果、时间冲突、技能堆砌、项目空泛和简历内提示注入。
- 日志只记录角色、Prompt、模型版本、token、耗时、状态和失败类型，不记录简历正文。

涉及技术：Spring AI Structured Output、Prompt 版本、服务端证据验真、Agent Evaluation、Prompt Injection 防护、隐私日志。

完成标准：固定样本能够输出稳定结构；模型引用全部通过服务端验真；无证据内容不会被包装成事实；攻击样本不能改变系统规则和工具边界。

### 3. 角色 Agent 固定评估

开发内容：

- 为证据审计建立事实准确率、证据合法率、信息缺失识别率、虚构率和结构解析成功率。
- 同时记录平均模型调用次数、token、估算费用、平均耗时和 P95 延迟。
- 保存脱敏结果和版本信息，不保存原简历、完整 Prompt 或模型建议正文。

涉及技术：Evaluation Driven Development、LLM-as-Judge 的有限使用、确定性服务端断言、模型/Prompt 版本治理。

完成标准：同一批样本可以重复运行和横向比较；能够解释指标能证明什么、不能证明什么。

### 4. 投递前工程收尾

开发内容：

- 验证 Docker Compose、数据库迁移、Qdrant collection、后端和前端的最小启动路径。
- 准备脱敏知识资料、简历和 JD 演示样本，以及一条五分钟完整演示路径。
- 更新项目总结、README、架构图、简历表述和核心面试追问。
- 不为演示新增复杂权限、招聘后台或与主流程无关的页面。

涉及技术：Docker Compose、Spring profile、配置隔离、健康检查、迁移脚本、可复现演示。

完成标准：新环境能够按文档完成资料导入、问答、模拟面试、复习和证据审计演示。

## 二、随后开发：投递前有余量则推进

### 1. 图工作流、HITL 和 checkpoint

进入条件：普通证据审计已经稳定出现证据失败修正、条件分支、人工确认暂停或进程恢复需求。

候选流程：

```text
提取简历事实 -> Java证据校验 -> 证据失败时最多修正一次
               -> 生成诊断和建议 -> 暂停等待用户确认
               -> 从checkpoint恢复 -> 输出最终结果
```

涉及技术：Spring AI Alibaba Agent Framework/Graph、状态图、条件边、有界循环、Human in the Loop、checkpoint、节点级日志。

完成标准：与普通 Spring AI 基线使用同一批样本比较修正成功率、完成率、恢复率、模型调用次数、费用和 P95 延迟。版本升级或持久化不稳定时，只保留隔离 POC，不改主链路。

### 2. Agent 调用链可观测性

开发内容：使用 Micrometer/OpenTelemetry 串联检索、Chat、Tool 和图节点，统一 requestId/traceId，观测 token、费用、延迟和错误类型；Prompt、简历和回答正文默认不采集。

完成标准：能够定位一次请求在检索、模型、工具或图节点中的具体失败位置，并说明敏感数据和高基数标签的控制方式。

### 3. 岗位匹配顾问和项目深挖面试官

进入条件：简历证据审计官已经稳定，且相同的证据、日志和评估治理模式经过验证。

- **岗位匹配顾问**：只用已验真事实和用户提供的 JD 做匹配，不把“简历未写”判断为“候选人不会”。
- **项目深挖面试官**：围绕真实项目生成基础、取舍、故障和扩展追问，可以只读检索知识库。
- **简历表达教练**：最后再做，只生成候选改写，不覆盖、持久化或投递简历。

第二个角色出现相同治理模式后，才提炼少量公共组件，不建设通用 Agent Runtime。

## 三、后续开发：投递后按条件进入

| 方向 | 进入条件 | 计划形态 |
| --- | --- | --- |
| MCP Server | 出现 Codex、IDE 或其他真实外部客户端 | 先暴露只读知识来源、检索和复习任务；写工具继续人工确认 |
| 结构化 Agent Memory | 建立用户身份、数据归属、冲突、过期和删除规则 | 只保存有来源的学习事实，不向量化全部聊天记录 |
| Hybrid Search、Sparse + Dense、rerank | 扩大语料后，查询拆分和章节扩展仍稳定漏召回 | 使用同一评估集比较质量、P95 延迟、费用和维护成本 |
| 多模型路由和降级 | 固定任务证明不同模型存在稳定质量/费用差异 | 低成本模型做抽取，强模型做复杂评价，并记录降级结果 |
| DOCX | 出现真实 DOCX 简历输入需求 | 只做本地文本提取和格式提示，不与 OCR 绑定 |
| 主题学习路径和间隔重复 | 现有题目、attempt 和复习日期能够形成跨会话学习事实 | 先做确定性推荐，再判断是否需要模型规划 |
| 公网部署 | 本地演示稳定并具备安全配置 | 增加反向代理、TLS、备份恢复和最小访问控制 |

## 四、明确延后或不进入主项目

- **OCR**：当前不开发；扫描件使用带文本层文件或手动粘贴，除非后续真实样本证明需求足够高。
- **A2A**：当前没有两个独立 Agent 系统，只保留协议学习或最小 POC。
- **Temporal**：只有出现跨分钟、跨重启的长任务且图 checkpoint 不足时再评估。
- **GraphRAG/Neo4j**：只有多文档、多实体、多跳固定样本证明向量 RAG 稳定失败时进入。
- **自由多 Agent、通用 Agent Runtime、AI Gateway**：当前不建设，不为了技术名称提前抽象平台。
- **语音视频、防作弊、多租户招聘平台、复杂权限后台**：与个人 Java 面试训练产品的当前定位不一致。
- **模型训练、微调、LLM Infra、Kubernetes**：不作为本项目主线，不在简历中包装相关生产经验。

## 开发停止规则

- 一个候选技术不能改善质量、恢复能力、成本或可解释性时，停止接入并保留实验结论。
- 同一时间只允许一个主要功能闭环和一个隔离 POC，不并行留下多个半成品。
- 投递前不再因为“技术更新”临时插入新框架；新方向先记录进入条件，投递后再评估。
- 已实现能力和未来路线必须分开维护；简历成果只引用 [项目技术栈与功能总结](08-项目技术栈与功能总结.md)。
- 项目掌握程度、学习范围和面试自测标准见 [面试准备与项目掌握要求](10-面试准备与项目掌握要求.md)。
