# 后续开发路线

> 更新时间：2026-08-13
> 用途：约束后续自主开发选题。每轮只推进一个可验证闭环，已完成事项及时更新，不把本文件写成开发流水账。

## 当前基础

项目已经完成版本化知识库、章节树、Qdrant 向量生命周期、资料检索与问答、模拟面试、证据化评分、复习 attempt、单会话复盘和受控 Tool Calling。

PDF 解析已具备逐页文本/图像分类、保守双栏重排和无文本页识别；当前确定性样本为 `8/8`，文本关键短语为 `35/35`。近期只继续验证带文本层 PDF，不开发 OCR。现有 RAG 固定集为 6 道题，全部首位命中，但语料较窄，尚不足以判断混合检索或 rerank 的收益。

## 推荐顺序

| 优先级 | 开发闭环 | 主要产物 | 验收标准 |
| --- | --- | --- | --- |
| P0 | 真实文本层 PDF 补证据 | 经授权脱敏的中文简历样本与基线报告 | 覆盖不同字体、嵌套表格和不规则侧栏；只验证文本层，只有稳定复现缺口才修改解析算法 |
| P0 | RAG 困难评估集 | 20 至 30 条精确术语、相似章节、标题路径、歧义、无答案和跨章节样本 | 至少输出 Hit@1、Recall@5、MRR、标题路径命中和拒答结果 |
| P1 | 检索增强对照 | 一项候选方案与当前 Dense 基线的对比报告 | 固定评估集证明质量提升，且延迟、费用和维护成本可接受 |
| P1 | 主题级学习事实 | 基于 `source + documentVersion + headingPath` 的单会话主题聚合 | 展示题数、attempt、最近/最好分、重复遗漏和练习时间，不虚构掌握度 |
| P1 | 连续学习路径 | 章节、查资料、问答、主题练习和复盘之间的显式入口 | 用户主动触发；不解析模型自然语言驱动页面或隐藏调用模型 |
| P2 | 部署与演示收尾 | 脱敏演示资料、3 至 5 分钟演示步骤和运行边界说明 | 新环境可按文档完成导入、问答、面试、复习和助手演示 |

## 特色方向：简历求职角色 Agent

这条路线作为主开发顺序之外的产品特色方向，不占用上方 P0/P1/P2 排序，也不替代 RAG 评估和学习闭环。它复用现有“简历/JD 解析、候选人画像、面试题、证据化评分和受控 Tool Calling”，把同一份用户确认事实交给不同专业角色完成明确任务。后续自主开发可以在主路线形成稳定闭环后选择其中一个角色推进，但一次只做一个可验证角色，不整体铺开。

这里的“角色 Agent”不是多 Agent 平台。第一阶段使用同一个 Java/Spring AI 服务，通过角色类型切换 Prompt、结构化输出、评价标准和工具白名单；角色由用户显式选择，角色之间不自动对话、不自行编排任务，也不自动修改简历。

### 角色顺序

| 顺序 | 角色 | 核心职责 | 主要输出 | 关键边界 |
| --- | --- | --- | --- | --- |
| 1 | 简历证据审计官 | 检查简历事实是否具体、完整、前后一致、可在面试中自证 | 事实清单、原文证据、模糊表述、缺失信息、风险等级、修改建议 | 只依据简历原文，不推测工作年限、技术深度和项目结果 |
| 2 | 岗位匹配顾问 | 将已验真的简历事实与用户提供的 JD 要求逐项对齐 | 已匹配证据、缺口、优先补强项、可追问题 | 不把“未写”判断为“不会”，不生成虚假经历 |
| 3 | 项目深挖面试官 | 围绕简历中的真实项目和技术选择生成递进追问 | 项目事实卡、基础题、取舍题、故障题、证据依据 | 可只读查询知识库；不能用资料库内容反向补写候选人经历 |
| 4 | 简历表达教练 | 在事实不变的前提下生成可选择的表达改写 | 原句、建议句、改写理由、事实来源、待用户确认项 | 只返回候选修改，不覆盖原文，不自动保存或投递 |

### 首个开发闭环：简历证据审计官

首个版本不同时实现四个角色，先完成一个端到端可验证闭环：

1. 复用当前 PDF/Markdown/TXT 简历读取和 `resumeText` 输入，不新增 OCR、对象存储或知识库导入。
2. 将简历拆为基本信息、技能、工作经历、项目经历、教育经历和成果数据等事实项；每项必须携带简历原文中的逐字证据。
3. 检查缺少时间、角色、动作、技术选择、结果指标、前后矛盾和无法自证的宽泛结论，但不把缺失字段补成事实。
4. 返回结构化问题清单和修改建议；用户确认前不生成“最终简历”，不覆盖上传正文。
5. 页面先展示事实与风险，再展示建议；用户可以按问题定位原文并决定是否采纳。

验收至少覆盖：

- 模型候选证据必须经 Java 服务端逐字包含校验，不在原文中的引文直接丢弃或标记失败。
- 固定样本覆盖完整简历、缺少量化结果、时间冲突、技能堆砌、项目描述空泛和包含提示注入文本六类情况。
- 输出区分“原文明示”“信息缺失”“角色建议”，不得把推断混入事实。
- 记录角色版本、Prompt 版本、模型、耗时、token、成功状态和失败类型，但不记录简历正文或建议正文。
- 默认不持久化简历；未来需要长期求职档案时，先增加用户确认、数据归属和删除机制。

### 后续组合方式

证据审计稳定后，岗位匹配顾问消费“已验真的简历事实 + 用户提供的 JD”，项目深挖面试官消费“已验真的项目事实 + 只读知识检索”，表达教练只消费用户选中的事实和问题。不同角色共享事实模型，但每次调用仍是独立、显式、可追踪的请求，不建立角色自由协作网络。

这条路线的项目特色应表达为：

> 基于可验真简历证据的 Java 求职角色 Agent，使用结构化输出、角色级工具白名单和服务端证据校验，完成简历审计、岗位匹配、项目深挖与受控改写。

## 检索增强选择规则

按评估暴露的问题只选择一项推进，不同时堆叠：

1. 标题或歧义问题召回差：先试确定性的 `source + headingPath + 原文` 上下文化索引。
2. 用户需要限定资料范围：增加来源过滤，并在页面明确展示搜索范围。
3. 短 Chunk 命中但回答上下文不足：验证父子索引或相邻 Chunk 扩展。
4. 精确术语遗漏：优先验证 Qdrant sparse + dense + RRF，不先引入 Elasticsearch。
5. 正确内容已召回但排名靠后：再验证 rerank。
6. 单次检索无法覆盖复杂问题：最后考虑有次数、token、耗时和只读工具限制的 Agentic RAG。

## 运维收尾

- 将共享 MySQL 5.7 的 `max_allowed_packet=1M` 写入服务器配置并在数据库、应用重启后复核；当前运行时调整不会跨数据库重启保留。
- 仅本机使用时让服务监听 `127.0.0.1`，不要放宽 Tomcat 非法 URL 字符。
- 用户本机 `storage` profile、`8080` 端口和前端代理属于本机配置，不作为所有环境默认值提交。

## 暂缓与条件型方向

- **OCR**：当前明确暂缓，不进入自主开发候选。无文本页继续提示用户改用带文本层文件或手动粘贴；只有用户重新明确提出需求后才讨论供应商、隐私、费用和人工确认。
- **DOCX**：当前不开放；真实样本证明有必要后，再单独评估本地解析能力，不与 OCR 绑定开发。
- **用户体系与跨会话趋势**：准备公网或跨设备使用后，再设计身份、归属、权限和删除规则。
- **MCP**：出现 Codex、IDE 或其他客户端复用当前资源/工具的明确需求后再做。
- **GraphRAG**：多文档、多实体、多跳评估证明普通 RAG 稳定失败后再选型。
- **多 Agent/A2A、通用 AI Gateway、提醒调度器**：当前没有业务证据，不进入近期路线。简历角色使用单服务、显式角色和受限工具，不因此放开多 Agent 平台边界。

## 每轮执行规则

1. 先读取真实代码、`docs/04-当前进度.md`、本文件和最新 Git 状态。
2. 从最高优先级中选择一个尚未完成、可在本轮验证的闭环。
3. 不为展示技术栈提前增加中间件、平台或 Agent 工具。
4. 完成后同步更新当前进度；核心能力或量化结果变化时更新 `docs/08-项目技术栈与功能总结.md`。
5. 若评估未证明收益，保留基线和结论，不继续实现对应技术。
6. 简历角色方向默认从“证据审计官”开始，一轮只实现一个角色闭环；不得因角色命名提前建设多 Agent 编排、共享记忆或自动改写链路。
