# 后续开发路线

> 更新时间：2026-09-23。本文件是后续开发顺序、阶段内容和验收标准的唯一权威来源；不重复维护已实现能力、历史过程和条件型问题详情。

## 一、路线判断

项目现有可信 RAG、文本面试、证据化评分、复习、简历角色和受控 Agent 已经形成基础产品。当前优先同步并吸收 InterviewGuide 的面试资料、教程和训练方法，在现有知识库、题库和复习链路中形成可用内容。上游工程实现作为学习材料和备选方案；本地实现更准确、可靠或适合 Java/Spring AI/Vue/MySQL/Qdrant/Lucene 技术栈时，不为对齐而替换。

融合遵循六个原则：

1. **学习成果优先**：按有使用权的主题分批吸收面试资料与开发案例，进入可阅读、检索、组卷或复习的路径；资料清单和只读调研不算完成，内容转化不强制新增 Java/Vue 代码。
2. **工程实现择优**：学习 InterviewGuide 的领域对象、状态、编排、幂等恢复和失败降级，但是否采用由本地真实问题和验证结果决定，不以实现同构作为验收。
3. **复用现有主干**：新增学习内容与能力接入现有知识库、题库、会话、评分和复习链路，不旁路建设第二套系统。
4. **主题完整交付**：每轮交付一批可实际使用的面试内容或一个可追踪的上游开发流程，不按接口、字段或孤立文档拆轮次。
5. **许可与来源清楚**：记录来源、commit、许可证、用途和变换方式；未经许可不复制 AGPL 源码、Prompt 或文档原文。
6. **保留本地优势**：不降低 Dense/BM25/Hybrid、Hard Negative、可靠拒答、引用/claim 校验和多存储治理能力；上游方案只在能弥补当前真实缺口时接入。

## 二、通用开发规则

- 每轮先定义用户能学到什么、在哪里阅读/检索/练习或追踪实现，以及最小验收标准。
- 内容主题先核对上游相关资料、来源与许可；工程流程主题再读取当前相关教程、实现与直接测试并记录 commit。在 `docs/06` 维护“上游概念 -> 本地内容/类/状态/表 -> 必要差异”的映射。
- 优先级为上游面试内容与开发方式吸收 -> 支撑该学习路径的本地适配；数据错误、隐私、重复费用和主流程阻塞可插队。其余 RAG 质量、容量与前沿扩展按真实样本和阶段进入条件处理，不因更容易验证而抢占学习主线。
- 主流程、关键成功/失败边界、重复操作、恢复入口和必要前端尽量同轮完成。
- 过程文档、测试、依赖检查、服务复核、外部调研和重复基线不能单独结项；经许可转化并进入真实使用流程的面试内容是学习成果。
- 普通闭环只更新 [当前进度](04-当前进度.md)；能力或简历口径变化时更新 [项目技术栈与功能总结](08-项目技术栈与功能总结.md)。
- 真实失败、环境告警和后备技术统一记录在 [问题清单](11-问题清单.md)，不在本文重复展开。
- 用户已授权必要的开发库 SQL 和付费 Chat/Embedding 验收，无需逐轮请求确认。SQL 在相关改动同轮执行并核对；付费调用前固定样本、指标、次数上限和失败后的保留/回退动作。生产数据和未经明确要求的破坏性操作不在此授权内。
- 同一时间只允许一个主要业务闭环；不并行启动多个大型子系统。

## 三、当前吸收顺序

1. 先按主题批量转化有使用权的 InterviewGuide 面试资料与 Skill/Rubric/追问，使其进入现有知识检索、题库和复习路径；记录来源与必要差异，并实际走通一条学习流程。资料使用权不明确时只保留链接与独立重写的概念，不复制原文。
2. 学习相应工程案例时再核对上游当前源码和测试；8.3 Skill/Rubric 与 9.1 任务恢复的上游映射只作学习资料，不再作为继续开发的前置门槛。
3. 9.2 索引临时构建与原子发布已完成；下一项大型工程闭环是 9.3 多模型 Provider 中心，先服务当前 Chat/Embedding 的配置、测试和结果追踪，不提前扩成通用 AI 网关。

阶段 7 的 storage 反馈回归、角色迁移、真实 RAG 失败、项目深挖评价和候选版本验收保留为条件型遗留；有真实阻塞或既定验收进入条件时处理，不再作为阶段 8-11 之前的固定门槛。

## 四、阶段 8：面试产品编排

阶段目标：把知识、简历、JD、项目事实、题目、评分和复习组织成统一的可配置面试产品。

### 8.1 面试配置与多来源出题

**用户结果：** 用户配置一场面试，预览和调整题目后开始正式面试。

**当前进度：已完成。** 五类 Skill、三档难度、草稿确认和配置快照已经接通；有简历时按约 60%/40% 并行生成简历题与 Skill/方向题，无简历时生成方向题，分支失败按 InterviewGuide `969e2af` 语义降级，双失败由 Skill 固定题补足。近期同 Skill 历史题的题面、类型和知识点摘要进入两路 Prompt，服务端再执行同场/历史规范化去重。正式确认使用客户端稳定 `requestId`、数据库唯一键和持久化查询恢复同一会话；草稿指纹只作为短期费用优化。草稿编辑/删除/替换、可信知识绑定、部分成功状态以及既有评分、报告和复习链路作为本地增强保留。相关逻辑已通过零费用定向测试和前端构建，真实付费模型题单质量验收尚未执行；必要时按已授权的费用边界开展，不阻塞当前上游学习主线。

**实现内容：**

- 保存面试类型、Skill、难度、题量、追问数、分类配额、知识来源和模型版本的配置快照。
- 组合 Skill 固定题、简历事实题、JD 匹配题、知识库题和项目深挖题。
- 按分类最小题量、优先级和总题数进行确定性分配。
- 增加同场去重和近期历史题排除。
- 生成结果先进入草稿，支持预览、编辑、删除、替换和确认。
- 题目不足时保留有效草稿，显示目标数、实际数和缺失分类。
- 模型失败时允许使用固定题兜底，不伪造模型成功。
- 确认后复用现有会话、评分、报告和复习链路。

**关键边界：** 重复提交不产生两套题单；输入资料变化后旧草稿失效；无效分类配额在模型调用前拒绝。

**验收：** 一场面试混合至少三种来源，用户修改题单后完成面试，并生成报告和复习任务。

### 8.2 知识库题库

**当前进度：首版已完成。** 已实现资料版本绑定题目、草稿编辑、审核启停、失效版本标记、异步生成、部分成功保留、显式恢复、模型超时、同资料版本活动任务互斥、人工/随机组卷、会话幂等和现有评分/报告/复习接入；下一步只有在出现真实失败样本时继续修复，不为理论完整性扩张。

**用户结果：** 用户从知识资料生成、审核并使用专项题库。

**实现内容：**

- 题目保存问题、答案要点、难度、分类、Rubric、固定追问和知识来源版本。
- 支持选择资料、题量、难度和追问数发起异步生成。
- 状态至少包含草稿、已审核、已停用和待复核。
- 支持编辑、审核、启停、删除、重新生成和筛选。
- 文档版本变化后将相关题目标记为待复核。
- 首版以 InterviewGuide 为基础语义，支持随机组卷和人工选题；按薄弱项组卷作为本地增强，在阶段 8.3 基于低分维度映射实现，不在题库层重复统计。
- 专项面试复用现有会话、评价、报告和复习。
- 保存题目使用次数和最近使用时间；聚合得分与低分维度映射在阶段 8.3 统一收口。

**关键边界：** 部分生成成功可以继续审核；失败部分可单独恢复；文档删除或回退后不能静默使用失效题目；模型答案必须关联当前知识证据。

**验收：** 完成“选择资料 -> 生成 -> 审核 -> 组卷 -> 面试 -> 低分复习”的完整流程。

### 8.3 Skill、Rubric 与专项训练

**当前进度：核心闭环和 8.3.x“上游面试资料学习包”系统化吸收已完成。** 19 份共享面试知识和 1 份 AI Agent 资料已一次性进入 storage，共 159 个 Chunk；在此基础上形成线程池、Spring 事务、MySQL、Redis、MQ、分布式可靠性、JVM、集合、JMM/AQS、Spring Bean、TCP/HTTP、操作系统、设计模式、高可用、算法和 RAG/Agent 共 16 门深化课程。最后 10 门批次新增 90 个一致 Chunk 和 30 道已审核题，每门均按所属 Skill 三项 Rubric `1/1/1` 组卷。后续只根据真实检索、作答、复习或求职方向缺口补充内容，不再以扩大文件数量为目标；具体运行链路需要时再吸收 Skill、Prompt 和公司专项约束。9.2 已完成，主开发顺序转入 9.3；上游工程实现仅在能补足真实缺口时学习或采用，本地已验证方案不为形式对齐而替换。

**用户结果：** 不同技术方向和公司专项拥有不同题目分布、追问和评价标准。

**实现内容：**

- 建立 Skill、分类、优先级、题量规则、参考知识和版本。
- 首批接入 Java 后端、系统设计、AI Agent/RAG 和算法；第二批接入公司专项、测试、前端和 Python。
- JD 解析结果可以生成一次性自定义 Skill，由用户确认分类。
- 通用 Rubric 覆盖准确性、原理、实现、边界、性能、并发、一致性、故障、恢复、取舍和验证。
- 项目深挖 Rubric 额外覆盖背景约束、替代方案、选择理由和恢复证据。
- 正式面试和复习 attempt 保存 Skill、Prompt、Rubric 和模型版本。
- 低分维度映射为明确复习任务和下次追问。

**关键边界：** Skill 版本变化不重写历史评价；JD 推断不能变成简历事实；无效配额不进入生成阶段。

**验收：** 同一输入选择不同 Skill 后，题目分布、追问和评价维度存在可解释差异，且均可完成复习再练。

### 8.4 简历中心

**当前进度：核心闭环已完成。** 已实现文件 Hash 去重、不可变版本历史、当前版本切换、完整正文显式保存边界、四类成功分析结果版本隔离、面试会话版本绑定和已确认事实版本比较；删除治理、派生分析异步化和对象存储按阶段 9 的统一恢复与文件治理进入，不在阶段 8.4 封板时另建平行机制。

**用户结果：** 用户显式保存和管理多份简历及版本，并关联审计、岗位和面试历史。

**实现内容：**

- 建立简历记录、文件版本、目标岗位、解析状态和分析状态。
- 文件 Hash 去重，明确复用或创建新版本。
- 分离文件解析、证据审计、岗位匹配和表达教练任务。
- 默认保存脱敏结构化事实和证据位置；完整正文必须由用户显式选择保存。
- 支持当前版本切换、历史版本比较和事实新增/删除/变化。
- 从确认的项目事实直接发起项目深挖。
- 面试会话绑定当时的简历版本，后续更新不改变历史解释。
- 删除简历时处理文件、派生结果和历史引用。

**关键边界：** 提示注入继续隔离；模型失败不损坏已确认事实；被历史会话引用的版本不能留下不可解释记录。

**验收：** 上传两版简历后可以比较事实变化，并选择任一版本完成岗位匹配、项目深挖和面试。

## 五、阶段 9：异步、索引与资源治理

阶段目标：让长任务、索引发布、模型配置和文件存储具备可恢复的工程边界。

### 9.1 统一异步任务恢复

**用户结果：** 长任务可查询、取消、恢复和重试，应用重启或 Worker 迟到不会破坏最终状态。

**实现内容：**

- 定义公共任务执行协议，但保留各业务自己的输入和结果。
- 每次执行生成 `attemptId`；领取、心跳、完成和失败均校验 `taskId + attemptId`。
- 记录 Worker、开始时间、最后心跳、恢复次数、进度和失败类型。
- 增加心跳节流、卡住任务扫描、自动补投和最大恢复次数。
- 丢弃旧 Worker 的迟到完成或失败结果。
- 保留排队取消，明确运行中取消和补偿边界。
- 应用重启后按任务类型恢复、重新排队或安全失败。
- 先用于资料索引、题库生成和简历分析；出现跨进程 Worker 后再接 Redis Stream。

**验收：** 确定性证明旧 attempt 不能覆盖新 attempt，重复消息不重复生成业务结果，重启后任务可恢复或得到明确终态。

### 9.2 索引临时构建与原子发布

**当前进度：已完成。** Dense/Qdrant 与 Sparse/Lucene 使用同一 generation 临时构建并校验，状态表以 `published_generation` 作为检索发布指针；发布更新同时校验 `building_generation + attempt_id`，旧 Worker 无法覆盖新 attempt。既有索引以 `legacy` 代兼容，首次成功重建后转为严格 generation 过滤。单路失败、旧 attempt、构建期检索和真实 storage 代际切换均已验证。

**用户结果：** 新索引完整前继续查询旧版本，部分 Dense/Sparse 数据不会进入正式检索。

**实现内容：**

- 索引任务增加 `generationId/jobId`。
- Dense 和 Sparse 先写临时版本或命名空间。
- 发布前校验文档版本、Chunk 数、索引契约和两路完成状态。
- 两路成功后切换当前 generation，再清理旧版本。
- 任一路失败时保持旧正式版本，并允许恢复失败 generation。
- attempt fencing 同时保护索引写入和发布。
- 巡检增加临时残留和错误 generation 诊断。

**验收：** 制造单路失败、发布前重启和旧 Worker 迟到后，查询始终只看到最后一个完整版本。

### 9.3 多模型 Provider 中心

**当前进度：下一主开发目标。**

**用户结果：** 用户配置和测试模型，为不同能力选择模型，历史结果可追踪模型来源。

**实现内容：**

- 管理 Provider、模型、能力类型、启停状态和功能级默认值。
- Chat、Embedding、ASR、TTS 独立配置。
- API Key 加密保存、脱敏展示且不进入普通日志。
- 提供连通性、结构化输出、Embedding 维度和语音能力测试。
- 模型调用记录模型、版本、token、耗时和错误类型，不记录敏感正文。
- Prompt、Rubric、数据集和模型共同形成运行契约。
- 进行中任务使用启动时配置快照，不受配置更新影响。

**验收：** 两个 Chat 配置分别完成固定样本运行并隔离保存结果；错误凭据、429、5xx、超时和维度变化均可识别。

### 9.4 文件与对象存储

**用户结果：** 知识文件和简历能够可靠保存、下载、解析和重试，长任务不依赖请求内正文。

**实现内容：**

- 定义文件对象键、Hash、大小、类型、用途和状态。
- 接入 S3 兼容接口，并保留 local 文件实现。
- 数据库保存文件元数据，任务只通过文件 ID 读取内容。
- 知识资料和简历使用不同保留、删除和隐私策略。
- 支持上传去重、下载、软删除和最终清理。
- 巡检对象缺失、孤立对象和孤立数据库记录。

**验收：** 上传后应用重启仍能继续解析；重复上传、解析期间删除和 Bucket 不可用均有明确结果，不产生无法识别的孤立文件。

## 六、阶段 10：实时交互与求职流程

### 10.1 实时语音面试

**用户结果：** 用户通过语音完成现有面试，语音失败时切换文字，结束后继续使用同一报告和复习链路。

**实现内容：**

- 建立语音会话状态机和 WebSocket 握手。
- 浏览器按序号采集和发送音频分片。
- 接入 ASR 临时/最终转写、手动提交和静音自动提交。
- 最终转写提交到现有面试会话，不新建第二套评分领域。
- 接入 TTS 流式播放、用户打断、重复音频过滤和回声控制。
- 增加 WebSocket 心跳、断线重连和会话恢复。
- 使用有界上下文摘要；ASR、LLM、TTS 分阶段记录状态和错误。
- 任一语音阶段失败时允许切换文字继续。

**验收：** 完成至少三题语音面试，主动断开一次后恢复；报告和复习结构与文字面试一致。

### 10.2 面试日程与求职流程

**用户结果：** 用户管理真实面试安排，并从日程进入准备、模拟和复盘。

**实现内容：**

- 管理公司、岗位、轮次、时间、方式、状态和备注。
- 日程关联 JD、简历版本、Skill 和准备资料。
- 提供日历和列表视图。
- 面试前生成准备清单和推荐复习任务。
- 从日程直接创建针对性模拟面试。
- 面试后记录真实问题和结果，人工加入题库或复习任务。
- 汇总同一公司和岗位的多轮进度。

**验收：** 创建日程后可以完成准备、模拟、真实问题记录和复习任务生成；时间修改、取消和重复生成保持一致。

## 七、阶段 11：评估与交付收口

### 11.1 评估实验中心

**用户结果：** 用户创建、恢复并比较检索、回答、评分和模型评估，明确决定候选是否采用。

**实现内容：**

- 统一数据集版本、dev/holdout、Git SHA、语料/Prompt/Rubric Hash、模型和索引契约。
- 检索、回答、评分和模型迁移保留不同指标，但共享运行、恢复和报告框架。
- 使用临时知识空间或独立评估数据库，不污染开发数据。
- 保存逐样本结果、失败层、阶段耗时和坏例。
- 支持单题和失败样本恢复，不重复调用成功样本。
- 对候选和基线生成同口径差异报告，并保存人工采用/回退结论。
- 展示检索、拒答、引用、claim、结构成功、token 和延迟指标。

**验收：** 完成一次基线与候选对照，运行中断后可恢复，并输出明确采用或回退结论。

### 11.2 产品与部署收口

**用户结果：** 新环境可以部署并运行完整的知识、简历、面试、复习、日程、模型、任务和评估产品。

**实现内容：**

- 收口工作台导航、空状态、错误恢复、任务进度和移动端基本体验。
- 提供后端和前端镜像。
- Compose 编排 MySQL、Qdrant、Redis、S3、后端和前端。
- 配置反向代理、HTTPS/WSS、健康检查和启动依赖。
- 建立数据库迁移和回滚边界。
- 演练 MySQL、Qdrant、Lucene、Redis 和对象存储备份恢复。
- 增加低敏指标、日志轮转和关键任务告警。
- 更新五分钟演示并冻结候选版本。

**验收：** 新环境按说明启动后，可完成文件上传、知识问答、题库面试、简历面试、语音面试、复习和评估核心路径，并完成一次备份恢复演练。

## 八、条件型质量问题

以下问题不进入固定阶段排期，出现真实证据时插入当前阶段处理：

| 方向 | 进入条件 |
| --- | --- |
| Sparse/Hybrid 拒答和查询理解 | 出现真实中文近域误答、误拒答或双路冲突 |
| PDF、Chunk、父子索引、Dense 结构前缀 | 出现真实解析、边界漏召回或上下文缺失样本 |
| Embedding 舱壁和容量 | 任务指标出现持续满载、排队、超时或拒绝 |
| 用户身份和知识空间 | 进入公网、多设备或多人共享场景 |
| Graph 工作流、MCP、多 Agent | 出现简单调用无法处理的分支、修正循环、外部客户端或跨系统协作 |
| OCR、DOCX、图片语义 | 出现稳定真实输入需求并能定义准确率和人工复核边界 |

具体证据和当前处理见 [问题清单](11-问题清单.md)。

## 九、长期技术边界

- Java 17、Spring Boot 3、Spring AI 和 Vue 继续作为主业务技术栈。
- MySQL 保存业务事实，Qdrant/Lucene 分别承担 Dense/Sparse 检索；不整体替换为 PostgreSQL/pgvector。
- Redis Stream 只在跨进程 Worker 或持久 Pending 恢复需求成立后接入执行通道。
- 语音复用现有面试会话、评分和复习，不发展第二套业务模型。
- 不建设候选人排名、自动录用、防作弊、多租户招聘平台、模型训练、LLM Infra 或通用 Agent Runtime。
- 参考项目源码只用于理解；实现必须符合本项目状态、隐私、证据和许可边界。

## 十、停止与切换规则

- 候选技术不能改善质量、恢复、成本或可解释性时停止接入，保留不采用结论。
- 已实现能力和未来路线分开维护；简历成果只引用 [项目技术栈与功能总结](08-项目技术栈与功能总结.md)。
