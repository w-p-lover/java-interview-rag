# 技术方案

## 当前原则

- 采用单体 Spring Boot 应用逐步演进。
- 后端以 Java 17 为主，构建工具使用 Maven。
- 当前基线使用 Spring Boot 3.5.16，并通过 Maven Wrapper 3.9.14 固定构建工具版本。
- HTTP 层使用 Spring MVC，独立项目开发端口为 `18080`。
- 前端使用 Vue 3、Vite、TypeScript、Vue Router、Axios 和 Sass，位于仓库内独立的 `frontend/` 子目录。
- 大模型应用优先使用 Spring AI。
- 关系数据库保存文档元数据、状态、日志和评估数据。
- 向量数据库保存 chunk 向量，具体产品在骨架阶段结合本机环境和实现复杂度确定。
- 第一版只支持 Markdown，避免文档解析范围膨胀。

## 核心数据流

```text
Markdown 文件或上传内容
→ Spring MVC 导入接口
→ 解析标题与正文
→ 生成文档版本和 chunk
→ Embedding
→ 向量入库
→ 用户问题向量化
→ 相似度召回
→ 上下文拼接
→ 模型回答
→ 返回来源
→ 保存召回与评估结果
```

## 当前 Web 架构

```text
frontend/src/api/          HTTP 客户端、接口与类型
frontend/src/components/   导入面板、处理链和 chunk 账页
frontend/src/router/       页面路由
frontend/src/styles/       主题变量与全局样式
frontend/src/views/        知识工坊页面
```

前端通过 Vite 开发代理访问 `/api`，代理目标为 `http://127.0.0.1:18080`。目录组织参考只读项目 `shoka-blog` 的 API、路由、视图、组件和 Sass 分层，但不复制其博客功能、UI 框架、Pinia 或其他当前不需要的依赖。

## 工程边界

- 文档元数据和向量记录必须可关联、可更新、可删除。
- 生成答案必须附带实际召回来源。
- 知识不足时明确兜底，不让模型伪造来源。
- 检索参数和 Prompt 变更应能够通过固定评估集比较效果。
- 新基础设施在需求出现后引入，不预先堆叠 Redis、MQ、Elasticsearch 或微服务。
- 当前导入登记只在应用进程内有效；页面刷新会丢失展示结果，后端重启会清空重复导入记录。

## 注释与可读性

项目新增代码注释默认使用简体中文，只解释不明显的业务意图、边界和原因，不为直观代码增加逐行说明。
