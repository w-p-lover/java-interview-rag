# 阶段路线

## 阶段 0：治理与最小骨架（已完成）

建立仓库规则、项目文档、Java 17/Spring Boot 3 骨架和无密钥配置边界。

## 阶段 1：Markdown/PDF 知识库（已完成）

完成 Markdown 与文本型 PDF 的文档元数据、版本识别、标题/页面解析和段落优先切分，标题层级、页码和 chunk 顺序可追踪。

## 阶段 2：向量生命周期（已完成）

完成 Embedding、Qdrant 写入、幂等导入、新版本替换、当前版本重建和来源级删除，并处理跨存储失败收敛。

## 阶段 3：RAG 问答闭环（已完成）

完成资料目录、章节树、原文检索、可靠回答、来源引用、知识不足兜底和可直接使用的 `/answer` 入口。

## 阶段 4：召回日志与 RAG 评估（基础闭环已完成）

已具备召回日志、固定题集、批量检索和回答要点评估。当前 6 道窄语料题均首位命中，下一步先扩充困难样本，不能据此直接宣称总体检索质量。

## 阶段 5：RAG 质量增强（评估驱动）

只有困难评估集证明稳定缺口时，才逐项验证上下文化索引、来源过滤、父子/相邻 chunk、稀疏混合检索或 rerank；新增延迟和费用必须与质量收益同时比较。

## 阶段 6：文本面试训练（已完成）

完成独立简历/JD 输入、画像、首轮问题、动态追问、逐题证据化评分、持久化会话和最终报告。简历材料与知识库保持独立数据生命周期。

## 阶段 7：学习闭环与受控 Agent（当前阶段）

已完成复习任务、多次 attempt、单会话历史、计划日期、最近会话入口，以及任务查询、进展复盘和确认改期三个受控工具。工具具备会话隔离、参数校验、写入确认、执行日志和请求级 token/耗时记录。

当前目标不是扩建通用 Agent 平台，而是：

1. 用困难评估和主题学习事实继续提高已有闭环的可验证性。
2. 从简历证据审计官开始，逐个完成有真实用户价值的角色 Agent。
3. 先建立普通 Spring AI 基线；出现修正循环、条件分支、HITL 或 checkpoint 恢复需求后，再让图工作流承担正式业务职责。
