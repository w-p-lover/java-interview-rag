# 阶段路线

## 阶段 0：治理与最小骨架

目标：建立仓库规则、项目文档和可运行的 Spring Boot 最小骨架。

验收：治理文档完整，构建文件和入口存在，最小启动或上下文测试通过，配置中没有真实密钥。

## 阶段 1：Markdown 知识库

目标：完成文档元数据、版本识别、Markdown 标题解析和 chunk 切分。

验收：相同版本不重复导入，标题层级和 chunk 顺序可追踪，边界场景有针对性验证。

## 阶段 2：向量生命周期

目标：完成 Embedding、向量入库、文档更新删除和手动重建。

验收：文档与向量关联清晰，新增、重复、更新、删除和失败状态可验证。

## 阶段 3：RAG 问答闭环

目标：完成问题检索、上下文生成、模型回答、来源引用和知识不足兜底。

验收：回答能够返回真实来源，无可靠来源时不会伪造依据。

## 阶段 4：召回日志与 RAG 评估

目标：记录检索参数、召回结果和耗时，建立固定评估集并批量比较结果。

验收：能够根据数据解释检索效果，并比较切分、topK、阈值和 Prompt 变更。

## 阶段 5：RAG 质量增强

目标：根据评估结果决定是否增加混合检索、rerank 和查询改写。

验收：新增能力必须有评估数据证明收益。

## 阶段 6：文本面试训练

目标：完成独立简历/JD 上传与自动解析、面试配置、提问、动态追问、逐题结构化评分和最终报告。

验收：资料库与面试输入在页面、接口和数据生命周期上清楚分离；用户上传简历后无需手工复制正文即可生成画像并完成一次文本面试，反馈包含知识来源、评分依据和改进项。文本粘贴仅作为备用输入。

## 阶段 7：学习闭环与 Agent 工程

目标：把逐题评价和复习任务推进为可重复练习、可比较、可追踪的学习闭环，再增加 Tool Calling、执行记录，以及实际需要出现后的 MCP。

实施顺序：

1. **复习任务闭环（已完成）**：从完成会话确定性生成任务，展示遗漏与真实知识来源，并支持幂等标记完成。
2. **二次作答 attempt（已完成）**：同一复习任务允许多次回答，但不改写原面试答案；每次保存 attempt 序号、评价、知识来源、Prompt/rubric/model 版本和时间，返回相对原回答及上次回答的变化。
3. **评分质量与可观测性（真实双运行基线已完成）**：已建立固定面试回答样本、服务端评分边界、无正文评价日志、运行/样本筛选、按版本汇总和稳定样本跨运行统计；`009`、`010` 已在隔离数据库执行。两轮 `qwen3.7-plus` 基线共 8 次 Chat 调用，四个可评分样本均落在预期范围，并产生首批同样本方差；两次观测不等同于长期稳定性结论。
4. **历史与趋势（单会话闭环已完成）**：已提供单会话和单任务 attempt 时间线，聚合首次、最近、最好分数及最近未解决遗漏；跨会话汇总仍须先明确数据归属。
5. **计划复习日期（已完成）**：在已有练习事实上增加可选日期及会话内状态/日期查询；没有真实提醒需求时不引入调度器。
6. **最小 Tool Calling（任务查询、进展复盘、受控写入、真实模型调用、人工确认、会话作用域、前端入口、请求级可观测和受限 HTTP 重试已完成）**：单会话任务查询、持久化复习进展分析和指定任务计划日期写入均已暴露为 Spring AI 工具，执行日志记录成功/失败、结果数、耗时和异常类型；受限助手只绑定这三个工具。完成页提供查询任务、复盘进展和调整计划入口，进展分析只消费已有 attempt 汇总且不返回回答正文；复盘后由前端基于持久化历史确定性选择当前可见的未练习或低分遗漏题，并直接定位到再次作答区，作答后可返回显式刷新复盘，不解析模型自然语言或自动产生新调用。当前会话由助手请求顶层结构化 `sessionId` 绑定到模型不可见上下文，三个工具都在业务调用前拒绝缺失上下文或跨会话参数；改期还由用户选择明确任务和日期，先得到助手回复，再确认结构化三元组。真实 `qwen3.7-plus` 已分别验证任务查询、改期和进展复盘；复盘基线中模型准确说明已练题从 `60` 提升到 `75`，并把空分数任务解释为尚未练习。请求级日志已能关联工具执行并记录最终响应状态、工具进入次数和累计 token。模型 HTTP 层只对连接失败/超时、429 和 5xx 最多重试一次，不在业务层重放工具。provider/model 回合数仍不推算，必要时的对话关联需由真实使用需求决定，再判断图工作流或 MCP。

验收：用户能针对真实遗漏再次作答，并看到有版本依据的前后变化；历史指标来自持久化 attempt 而不是前端临时计算；评分变更可解释；工具调用边界清楚、参数受控、结果不泄漏正文，真实模型调用和失败处理可追踪后再扩张，不建设通用 Agent 平台。

## 调整原则

阶段顺序用于控制主线，可以在阶段内部自主调整任务；RAG 闭环和评估完成前，不把主要精力转向后续 Agent 功能。

## 长期优化候选：GraphRAG

GraphRAG 不是当前阶段的默认技术路线。普通 RAG 继续负责按语义相似度召回真实 Chunk；只有出现跨文档、多实体、多跳关系问题，并通过新增评估用例确认普通向量检索存在稳定缺口时，才进入 GraphRAG 方案验证。

候选图关系可以围绕以下实体建立：

```text
候选人 → 项目 → 技能 → 岗位要求
面试题 → 回答 → 薄弱项 → 知识资料 → 复习任务
```

验证顺序为：先补多跳问题评估集，再尝试轻量关系模型或 MySQL 节点/边表，证明收益后才考虑 Neo4j 等图数据库。验收指标至少包括多跳来源命中率、回答依据可解释性、更新一致性和相对普通 RAG 的明确收益；没有数据收益时不引入。
