# Phase 13：项目深挖持久化评分闭环

## 阶段目标

把审计确认项目生成的固定四道深挖题，从准备页预览能力接入现有面试会话，使用户能够连续作答、获得证据化评分、查看最终报告并恢复历史会话。

## 完成内容

- 新增 `STANDARD` 与 `PROJECT_DEEP_DIVE` 显式会话模式，模式随会话写入和恢复，历史数据兼容为 `STANDARD`。
- 新增项目深挖会话启动接口，使用确认项目事实构造最小画像，把基础、取舍、故障和扩展四题映射为现有题目模型。
- 固定 `maxQuestionCount=4`，复用现有回答评价器但不允许追加第五道动态追问；第四题后复用原报告聚合。
- 前端支持直接开始项目深挖，并在进度、报告和最近会话中显示模式。
- 新增并执行 `017_interview_session_mode.sql`；共享 MySQL 5.7.36 的 `java_interview_rag` 中字段已核验为 `VARCHAR(32) NOT NULL DEFAULT 'STANDARD'`，当前会话行数为 0。
- 以临时 `storage` 实例真实调用项目深挖启动与恢复接口，返回 `PROJECT_DEEP_DIVE`、4 道题和上限 4；临时脱敏会话随后清理。

## 验证结论

- 20 个直接相关后端测试通过，覆盖启动、题数上限、模式持久化、历史行恢复、接口契约和受字段变更影响的复习服务；另完成一次真实迁移结构核验。
- 前端 `npm run build` 通过，包含 `vue-tsc --noEmit`。
- Playwright Mock 跑通简历审计、深挖启动、四次答题、最终报告和最近会话恢复；桌面与 375px 无横向溢出，控制台 0 错误、0 警告。

## 边界

- 本阶段未调用真实 Chat、Embedding 或 Qdrant；MySQL 执行了用户明确要求的 `017` 迁移，并完成一次真实 storage 会话写入/读取后清理临时数据。
- 知识资料仍需用户显式开启，只作为答题背景，不推断或补写候选人的项目事实。
- 没有新增第二套会话表、评分器、Chat 出题、图工作流或通用 Agent Runtime。

## 下一步

随后用脱敏固定数据完成五分钟演示路径；若没有固定四题覆盖不足的真实证据，不扩展自由追问。验证继续按风险做最小必要检查，不把测试数量作为开发目标。
