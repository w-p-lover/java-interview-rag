- 地址：https://github.com/interviewstreet/hiring-agent
- 定位：简历结构化解析、GitHub 信号补充和可解释候选人评分流水线。
- 可借鉴：多阶段处理、Prompt 模板、结构化输出、评分标准、证据说明、中间结果缓存和模型供应商抽象。
- 不适合直接采用：Python 主技术栈、招聘方筛选定位、GitHub 候选人评分和第一阶段 PDF 解析。
- 当前判断：保留为评分与评价流水线参考，等进入结构化面试评分阶段再深入研究。
- 许可证：MIT；如后续复用具体代码必须保留并遵守相应许可要求。

## 反 AI 模板化产品界面调研

- 资料：Studio Five《Beyond the Template: Overcoming the 4 Biggest AI Web Design Challenges in 2026》，https://studio5creative.com/overcoming-ai-web-design-challenges-in-2026/
- 问题：通用生成工具根据历史样本产出统计平均布局，容易形成重复结构、通用文案、品牌资产缺失和脱离用户路径的视觉页面。
- 可借鉴：先确定用户任务和信息流，再固定颜色与字体；使用生成能力完成基础结构后，人工调整业务层级、状态、控件和关键细节；对生成结果执行性能、语义和可访问性检查。
- 本轮采用：删除与求职任务无关的 hero、装饰网格、渐变、徽章、英文标签和技术管线主视觉；使用中性产品主题、标准控件、真实导入状态和求职训练主线。
- 未采用：手绘插画、纹理、Brutalism 或为了“反 AI”而制造另一套强风格；当前是工作型产品界面，优先信任感、信息清晰和操作效率。
- 许可证：本轮只采纳公开文章中的通用设计判断，没有复制代码、图片或其他受保护资产。

## blog-springboot 存储接入方式

- 参考范围：只读检查 `pom.xml`、`application.yml`、`docker-compose.yml`、私有配置示例、`AiVectorStoreConfig`、`AiArticleServiceImpl` 和 `AiRagServiceImpl`。
- 关系数据库：参考其 MySQL、Druid、MyBatis-Plus、环境变量和 `t_` 表前缀方式；根据用户后续明确要求，只读复用主项目 `.env` 的服务器地址和凭据，但使用独立数据库 `java_interview_rag`，不复用任何业务表。
- 向量库：参考其 Spring AI、Spring AI Alibaba、DashScope `text-embedding-v3`、Qdrant 1.10.1 和非阻塞启动探测；本项目使用独立 collection `java-interview-rag-chunks`。
- 适配判断：主项目的 Druid 1.2.14 旧 Starter 不适合当前 Spring Boot 3.5.16，本项目使用相同连接池产品的 Boot 3 专用 Starter 1.2.28；没有复制 Redis、RabbitMQ、Elasticsearch、聊天模型或文章业务代码。
- 修改边界：本轮未修改 `D:\IdeaProjects\blog\blog-springboot` 的任何文件；用户明确授权新项目只读使用其 `.env` 连接服务器，敏感值没有复制到新仓库、日志或文档。
