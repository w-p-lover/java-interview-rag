# 技术决策记录

## 记录格式

重要决策按“背景、选项、决定、理由、影响、回看条件”记录。普通类名和局部实现不需要单独建条目。

## ADR-001：主项目与新项目保持独立

- 背景：`blog-springboot` 已经具备内容平台、RAG 和 AI 任务治理能力，并在持续修改。
- 决定：`java-interview-rag` 使用独立仓库，主项目仅允许只读参考。
- 理由：避免并发修改冲突和重复建设，使新项目专注 RAG 评估与面试训练能力。
- 影响：所有写入和自动开发只发生在本仓库。
- 回看条件：无；这是长期项目边界。

## ADR-002：采用有边界的自主开发

- 背景：定时任务需要持续推进，不因普通技术选择频繁申请用户意见。
- 决定：允许自主选择可逆、简单、符合定位的方案；只有真实费用、密钥权限、不可逆操作、许可证冲突和核心定位冲突等硬阻塞才等待用户。
- 理由：提高持续开发效率，同时控制安全和方向风险。
- 影响：重要选择必须记录，局部阻塞优先绕开并推进其他安全任务。
- 回看条件：自主修改连续造成方向偏离或无法验证的改动时。

## ADR-003：允许正常 Git 开发流程

- 背景：自主开发需要为每个已验证闭环保留清楚、可回溯的版本记录。
- 决定：允许自主使用 `codex/` 分支、暂存和提交直接相关改动；远程配置明确时允许正常 push 当前开发分支。
- 理由：让定时开发形成小而完整的提交，便于检查、回退和持续推进。
- 限制：禁止强推、重写历史、覆盖用户改动、自动合并主分支、擅自创建或合并 Pull Request。
- 回看条件：项目接入明确的分支保护或 Pull Request 工作流时。

## ADR-004：阶段 0 使用最小 Spring Boot 依赖基线

- 背景：阶段 0 只要求建立可运行骨架，Web 接口、Spring AI、数据库和向量存储尚无已实现业务。
- 选项：一次性引入后续候选依赖，或只引入 Spring Boot 基础启动与测试依赖。
- 决定：使用 Java 17、Spring Boot 3.5.16、Maven Wrapper 3.9.14，只引入 `spring-boot-starter` 和 `spring-boot-starter-test`。
- 理由：满足最小启动和上下文验证，同时避免在需求与环境未确定前锁定无用依赖；3.5.16 是实施时 Maven Central 可用的最新 Spring Boot 3.x 稳定版，符合既定 Boot 3 边界。
- 影响：后续每项能力在出现真实业务和针对性测试时再增加所需依赖。
- 回看条件：进入需要 HTTP 接口、持久化、Spring AI 或向量存储的具体任务时。

## ADR-005：Markdown 内容版本使用规范化换行后的 SHA-256

- 背景：阶段 1 需要稳定识别文档内容版本，并避免 Windows 与 Linux 换行符差异导致相同内容被当成新版本。
- 选项：使用时间戳、对原始字节直接摘要，或先统一换行符再计算内容摘要。
- 决定：保留独立的文档来源；将 `CRLF` 和 `CR` 统一为 `LF` 后，按 UTF-8 内容计算 SHA-256 作为版本标识。
- 理由：结果确定、跨平台稳定、无需新依赖；来源不进入摘要，后续以“来源 + 版本”判断同一来源的重复导入。
- 影响：只有换行风格不同的内容版本相同；空格、标题和正文等其他内容变化仍会生成新版本；不同来源即使内容相同也保持为不同文档。
- 回看条件：实际语料出现需要忽略 BOM、尾随空格或其他格式差异的重复导入问题时。
