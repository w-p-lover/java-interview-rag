# 需求边界

## 当前产品边界

项目当前必须保持以下闭环可用：

- **版本化知识库**：Markdown 导入、标题/段落切分、内容版本、向量新增替换删除重建、当前章节树和来源淘汰。
- **可追溯 RAG**：资料目录、原文检索、可靠回答、来源引用、知识不足兜底、召回日志和固定评估集。
- **文本面试**：目标岗位、简历和可选 JD 生成画像与问题，支持动态追问、证据化评分、持久化会话和最终报告。
- **复习闭环**：从真实遗漏生成任务，支持计划日期、多次 attempt、分数变化、单会话历史和继续练习。
- **受控 Tool Calling**：工具白名单、会话作用域、写入人工确认、请求/工具日志和有限模型重试。
- **可用前端**：资料库、问答、面试、复习和助手均有明确入口，模型调用必须由用户显式触发。

## 输入与数据边界

| 输入 | 业务入口 | 用途 | 默认持久化/向量化 |
| --- | --- | --- | --- |
| Java 面试资料、项目说明、学习文档 | 资料库 | RAG 回答、出题和评分依据 | 是 |
| 候选人简历 | 面试/简历角色 | 画像、个性化出题和证据审计 | 否 |
| 岗位描述 JD | 面试/简历角色 | 岗位要求与简历事实对齐 | 否 |

- 简历和 JD 不复用知识库版本登记与向量生命周期，默认不保存原文、画像或建议。
- 面试文件只支持不超过 10 MiB 的带文本层 PDF、Markdown 和 TXT；无文本页提示用户检查或手动补充。
- 简历事实、回答证据和知识证据必须由 Java 服务端校验，不能把模型推断直接写成用户事实。
- 浏览器只保存最近会话 UUID，不保存简历、回答、评分、报告或知识正文。

## 允许后续实现

后续选题和验收统一以 [后续开发路线](09-后续开发路线.md) 为准，主要允许：

- 扩充 RAG 困难评估集，并在数据证明收益后逐项验证检索增强。
- 基于持久化题目、attempt 和标题路径形成主题学习事实与连续学习入口。
- 从简历证据审计官开始，逐个实现受控的简历求职角色 Agent。
- 真实出现条件分支、有界修正循环、HITL 或 checkpoint 恢复后，引入图工作流并与简单基线对照。
- 明确用户身份和数据归属后，再设计长期求职档案、跨会话趋势、历史原文或软删除恢复。

## 当前明确不实现

- 纯 Python 主后端、模型训练/微调、LLM Infra 或低代码平台替代核心实现。
- OCR、语音视频、防作弊、组织管理、多租户招聘平台和大型后台。
- 自由协作的多 Agent/A2A、通用 Agent Runtime、AI Gateway 和无真实需求的提醒调度器。
- 没有评估收益时的混合检索、rerank、GraphRAG、Neo4j 或新中间件；Hybrid 只能先作为独立可观测对照链路，未经固定题集和回答层验证不得替换生产策略。
- 没有数据归属前的后端全量会话列表、跨浏览器历史、长期简历保存或自动投递。

## 变更规则

用户最新明确需求可以调整本文件。自主开发可以细化实现顺序，但不得自行改变 Java AI 应用、RAG 和受控 Agent 的长期定位。
