# 需求边界

## 当前产品定位

项目是面向个人求职者的 Java AI 面试知识库与智能训练平台。核心价值不是功能数量，而是把知识资料、可信 RAG、个性化面试、证据化评分和重复练习连接成可运行、可恢复、可解释的学习闭环。

当前必须持续可用的主链路：

- **版本化知识库**：Markdown、TXT、文本型 PDF 导入，结构化解析与切分，内容版本、索引生命周期、历史回退和一致性巡检。
- **可信 RAG**：Dense、字段化 BM25、Hybrid-RRF、可靠拒答、来源引用、claim 证据校验、召回日志和固定评估。
- **文本面试**：目标岗位、简历、JD 和知识资料驱动出题，支持动态追问、结构化评分、会话恢复和报告。
- **复习闭环**：从回答遗漏或知识证据问题生成任务，支持计划日期、多次 attempt、同题再练和进步比较。
- **受控模型能力**：模型负责生成和评价，Java 负责状态、权限边界、证据验真、幂等、人工确认和失败恢复。
- **可操作前端**：资料、问答、面试、复习、任务和观测均有明确入口，付费模型调用必须由用户显式触发。

## 输入与数据边界

| 输入 | 业务用途 | 默认持久化 | 默认向量化 |
| --- | --- | --- | --- |
| Java 面试资料、项目说明、学习文档 | RAG、出题、评分依据和复习 | 是 | 是 |
| 候选人简历 | 事实审计、个性化出题、岗位匹配和项目深挖 | 否；后续简历中心必须由用户显式保存 | 否 |
| 岗位描述 JD | 岗位要求、面试配置和题目分配 | 否；后续日程或简历中心可保存脱敏版本 | 否 |
| 面试回答 | 评分、报告和复习 attempt | 按会话保存 | 否 |
| 语音音频 | ASR 和语音面试 | 后续默认不长期保存原始音频 | 否 |

- 简历和 JD 不复用公共知识库的版本登记与向量生命周期。
- 简历事实、回答证据和知识证据必须由 Java 服务端校验，模型输出不能直接写成用户事实。
- 当前面试文件支持不超过 10 MiB 的带文本层 PDF、Markdown 和 TXT；扫描页只识别风险并提示，不伪造 OCR 结果。
- 浏览器当前只保存最近会话 UUID，不保存简历、回答、评分、报告或知识正文。

## 后续允许融合的产品能力

后续开发以 [后续开发路线](09-后续开发路线.md) 为唯一顺序来源，允许在现有主线中逐步融合：

- 面试配置快照、Skill 分类配额、简历/JD/知识库/项目多来源出题、题目草稿和历史题去重。
- 知识库题库、答案要点、Rubric、固定追问、人工审核、专项面试和低分复习。
- 多 Skill、公司专项、自定义 JD Skill 和项目深挖评价。
- 用户显式保存后的简历中心、版本比较、异步分析和关联面试。
- 统一异步任务协议、attempt fencing、心跳、卡住任务恢复和旧 Worker 结果隔离。
- Dense/Sparse 临时索引构建、完整校验和原子发布。
- Chat、Embedding、ASR、TTS 的多模型 Provider 管理。
- S3 兼容对象存储、本地存储降级和文件生命周期治理。
- 复用现有面试领域的实时语音交互，以及面试日程、准备和复盘流程。
- 统一评估实验中心、完整容器交付和备份恢复演练。

这些方向属于后续阶段，不等于当前已实现能力，也不允许同时铺开多个半成品。

## 条件型质量能力

以下方向只在真实失败、容量或部署证据出现后进入，具体问题统一维护在 [问题清单](11-问题清单.md)：

- Sparse 中文近域拒答、Hybrid 冲突、查询理解和复杂 rerank。
- 复杂 PDF、有限 overlap、父子索引、Dense 结构前缀、DOCX 和 OCR。
- Embedding 独立舱壁、全链路 deadline、容量压测和跨实例观测。
- 用户身份、知识空间、访问控制和跨设备历史。
- GraphRAG、图工作流、MCP、A2A 和多 Agent。

## 长期禁止偏离的方向

- 不把项目改造成纯 Python AI 项目、模型训练项目、LLM Infra 或低代码平台。
- 不建设候选人排序、自动录用决策、防作弊监控、组织管理或多租户招聘平台。
- 不为了对齐参考项目替换 Java 17、Spring Boot 3、Vue、MySQL、Qdrant 或 Lucene。
- 不为了展示技术栈提前拆微服务、引入消息队列、图数据库、Kubernetes 或通用 Agent Runtime。
- 不把调研、文档搬运、扩题、重复基线或依赖检查当作单轮开发成果。

## 变更规则

用户最新明确需求可以调整本文件。调整后仍须保持 Java AI/RAG 面试训练主线、隐私边界、证据校验和可恢复业务状态；新能力必须进入现有产品流程，而不是旁路建设第二套系统。
