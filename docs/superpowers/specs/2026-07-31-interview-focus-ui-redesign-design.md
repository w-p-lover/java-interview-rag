# 专注面试台界面重设计

## 背景

当前 `/interview` 已具备简历/JD 上传、动态出题、逐题回答、评分、报告、复习任务和二次作答能力，但页面仍沿用早期“产品介绍 + 大卡片工作台”结构。首屏大标题、英文技术标签、编号式区段、重复说明和暖米色纸张风格让用户先阅读产品说明，再进入真正任务；`RAG`、并发覆盖、Prompt/rubric/model 等实现信息也占用了主要界面。

本次仅重设计前端视觉、信息结构和用户文案，不改变 API、业务状态、数据字段或后端行为。

## 调研结论

本轮检查了公开可访问的 Linear、LeetCode、Teal Job Tracker 和 Readwise Reader 界面：

- Linear：产品感来自稳定应用框架、紧凑状态条、主任务优先和次要属性侧置，不依赖装饰性 Hero。
- LeetCode：题目、作答、运行结果使用明确分区；辅助内容通过标签页或折叠按需出现。
- Teal：求职产品围绕当前进度和下一步操作组织，不在主路径解释内部技术。
- Readwise：学习记录采用低干扰阅读层级，历史和辅助功能不与当前任务争夺注意力。

不复制这些产品的布局或素材，只采纳“任务优先、状态紧凑、辅助信息侧置、文案简短”的共同模式。

## 设计目标

1. 用户进入 `/interview` 后在首屏直接看到完整的面试准备入口，而不是营销式介绍。
2. 面试中始终只有一个主要任务：阅读当前题目并作答；上一题反馈位于次要侧栏。
3. 面试完成后先看结果，再进入复习；普通用户不直接面对内部评价版本术语。
4. 所有文案从用户角度描述动作和结果，删除解释开发实现、反驳假设或强调“AI/RAG”的句子。
5. 在 320、375、414、768、1440 px 宽度下保持可读、无横向滚动、按钮文字不换行。

## 视觉方向

- 产品场景：求职者在桌面或笔记本上进行 30–60 分钟的专注模拟面试，需要清醒、低干扰、能快速扫描状态的浅色界面。
- 类型：产品 UI，现代极简、克制、工作导向。
- Hallmark：`Split Studio`，区别于上一版 `Workbench`；导航从 `N13` 调整为 `N9`，页脚从 `Ft2` 调整为紧凑 `Ft4`。
- 颜色：中性浅灰白工作区、纯白内容面、石墨正文、珊瑚红主操作、蓝色信息、绿色资料依据/进步状态。不得使用渐变、玻璃、装饰网格或暖米色主背景。
- 字体：产品界面使用单一无衬线字体栈，中文优先 `PingFang SC / Microsoft YaHei`，西文优先 Geist；等宽字体仅用于分数、题号和版本信息。
- 圆角：控件 6 px、内容面 8 px；不使用大于 16 px 的卡片圆角。
- 层次：主要依靠背景层、分栏、间距、选中态和细边界；不使用“边框 + 大模糊阴影”的浮卡组合。
- 动效：仅使用 120–220 ms 的状态反馈；不做页面入场编排，支持 `prefers-reduced-motion`。

## 信息结构

### 全局导航

保留产品名、`资料库`、`面试训练`、区段查找和状态，但改为紧凑单行应用导航。产品副标题、`面试台就绪` 等无决策价值的文本在窄屏隐藏。当前路由使用明确选中态。

### 未开始

删除 `TEXT INTERVIEW / RAG GROUNDED`、大 Hero、三行能力定义和底部技术口号。页面以以下内容开场：

- 标题：`开始一场模拟面试`
- 说明：`上传简历，选择目标岗位。题目会根据你的经历和岗位要求生成。`

配置区使用两栏：

- 主栏：目标岗位、简历、可选岗位描述。
- 侧栏：题目数量、本次材料状态、主按钮。

文件控件只保留当前文件、支持格式和本地/临时处理边界。文本粘贴入口改成可展开的备用入口，避免两个大文本框默认占满首屏。

### 面试进行中

新增 `InterviewSessionBar`，显示目标岗位、`第 N / M 题`、进度和退出操作。主区域使用稳定双栏：

- 左侧：题目、回答输入、提交操作。
- 右侧：上一题反馈；首题时显示简短空状态。

题目中的资料状态改为 `有资料参考` 或 `仅根据回答评价`。知识来源默认折叠。按钮忙碌文案统一为 `正在提交…`，不在按钮中解释评分和追问逻辑。

### 面试完成

报告先显示综合分和技术/完整/表达三个维度，再显示 `本场表现` 与 `需要补充`。主操作为 `开始新面试`。

复习区使用自然词汇：

- `复习题目`，不用 `复盘清单 / ITEMS`。
- `第 1 次复习回答`，不用 `Attempt 1`。
- `评价信息` 折叠区内显示 Prompt/rubric/model，主视图只显示分数变化和改进建议。

`标记完成` 是次要操作，`再次作答` 是复习任务的主要操作。提交复习回答不自动修改任务完成状态，保持现有业务语义。

## 文案规则

- 禁止英文 eyebrow、装饰性编号、`RAG grounded`、`chunk`、`Prompt/rubric/model` 等内部术语出现在主路径。
- 不使用“这不是……”“不会被并发覆盖”“不是固定只有三道”等辩解式文案。
- 标签只负责命名，帮助文本只解释当前操作，按钮只描述点击后的动作。
- 错误信息保留现有事实和恢复方式，不使用情绪化道歉。
- 不虚构通过率、用户数量、面试效果或其他指标。

## 组件边界

- `InterviewView.vue`：仅组合未开始、进行中和已完成三个状态。
- `WorkspaceHeader.vue`：全局导航、区段查找和响应式导航。
- `InterviewSessionBar.vue`：进行中/完成状态、题目进度和退出操作；props 下发，`reset` 事件上抛。
- `InterviewSetupForm.vue`：准备表单布局和提交，不持有 API 状态。
- `InterviewTextFileField.vue`：单个文件提取、状态和备用文本展开。
- `InterviewQuestionPanel.vue`：当前题目、资料折叠、回答输入和提交。
- `InterviewFeedbackPanel.vue`：上一题评分、优势、遗漏和建议。
- `InterviewReportPanel.vue`：整场结果和新面试操作。
- `InterviewReviewTaskPanel.vue`：复习任务列表、完成状态和知识来源。
- `InterviewReviewAttemptPanel.vue`：单任务再次作答和历史记录。

继续使用现有 Composition API、`<script setup lang="ts">`、typed props/emits 和 `useInterviewSession`；不引入 Pinia或新路由。统一使用 `lucide-vue-next` 图标，不绘制自定义 SVG。

## 状态与可访问性

- 所有按钮、输入、选择、文件控件覆盖默认、hover、focus-visible、active、disabled、loading、error/success 状态。
- 触摸目标最小 44×44 px；按钮和导航标签不换行。
- 输入标签始终可见；placeholder 仅作为示例，不承担标签职责。
- 边框宽度在状态切换时保持不变，焦点使用独立 outline，避免布局抖动。
- 资料来源、备用文本和评价信息使用原生 `details/summary` 渐进展开。
- 颜色不作为唯一状态信号，保留文字和图标说明。

## 验证

1. `npm run build` 通过 Vue TypeScript 检查与 Vite 生产构建。
2. 通过浏览器 Mock 或可控本地状态验证未开始、面试中、完成和复习 attempt 四类页面。
3. 检查 320、375、414、768、1440 px：无横向滚动、无文本遮挡、主按钮不换行、双栏正确折叠。
4. 检查键盘焦点、details 展开、文件输入、提交忙碌态和控制台错误。
5. 执行 Hallmark 58 项反模板检查和基本文字/背景对比度检查。

## 范围外

本轮不修改后端、接口、数据库、面试逻辑、评分策略、路由结构、认证、暗色模式、动画库或用户未提交的 `application.yml` 端口改动。
