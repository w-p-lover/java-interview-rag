# 求职面试工作台产品界面设计

## 背景

项目的目标是帮助 Java 求职者解析简历、结合目标岗位进行模拟面试，并使用知识资料辅助回答、追问、评分和复习。现有页面把阶段 1 的 Markdown 导入与 chunk 检查能力当成产品首页，导致用户看不出求职训练价值，也形成了明显的生成式 AI 页面风格。

## 产品定位

首页定位为“求职面试工作台”，围绕以下主线组织信息：

```text
求职目标与简历
→ 资料准备
→ 模拟面试
→ 训练反馈
→ 薄弱项复习
```

本轮只调整首页表达和现有导入区域的产品语义，不伪造尚未实现的候选人画像、模型问答、动态追问或评分结果。Markdown 导入、标题解析和 chunk 展示保留为资料准备阶段的真实能力，后续可下沉到资料库页面。

## 页面结构

```text
┌──────────────────────────────────────────────────────────┐
│ 面试准备台        求职档案  面试训练  资料库  训练记录      │
├──────────────────────────────────────────────────────────┤
│ 求职面试工作台                         阶段 1 / 资料准备   │
│ 先导入简历和岗位资料，再进入模拟面试                      │
├──────────────────────────────┬───────────────────────────┤
│ 当前准备                      │ 导入检查                  │
│ 简历或岗位资料上传             │ 版本 / 标题 / 切片状态     │
│ 当前真实可用能力说明           │ chunk 明细                │
└──────────────────────────────┴───────────────────────────┘
```

当前首页的主要操作是“导入简历或岗位资料”。未来模块以导航和状态占位表达，但不提供没有后端支持的假操作。

## 视觉原则

- 使用浅色中性产品界面，避免默认暗色科技感。
- 使用一套系统无衬线字体，不再使用大号衬线 hero 字体。
- 删除装饰性网格、渐变、发光点、泛化编号、宽阴影和超大圆角。
- 使用 8px 级别的边界和 8px 圆角；颜色只用于主操作、成功、重复、错误和处理中状态。
- 保留一条低调的产品流程导航，但让顺序表达真实求职训练阶段，而不是技术管线。
- 文案使用“简历、岗位资料、导入检查、开始面试、训练记录”等用户能理解的术语。
- 保留键盘焦点、响应式布局、减少动效和可读对比度。

## 验证标准

- 首屏能够在不阅读代码的情况下说明系统服务求职面试准备。
- 用户仍能上传 Markdown 并看到首次导入、重复导入和 chunk 明细。
- 前端类型检查与生产构建通过。
- 在桌面和 390×844 移动端没有横向溢出、文字重叠或不可见操作。
- 不新增数据库、模型调用、认证或未实现的训练结果。
