# 固定 RAG 评估语料设计

## 背景

固定题集和批量检索接口已经存在，但仓库没有与 `expectedSources` 对应的可复现 Markdown 语料，当前无法稳定运行真实来源命中评估。

## 方案

在 `evaluation/corpus/` 保存 5 份 UTF-8 Markdown：6 道题中线程池和 `volatile` 共用 `java/concurrency.md`，其余题目各使用一个精确逻辑来源。语料包含题集要求的核心事实和少量同主题解释，通过现有导入、切分、Embedding 与 Qdrant 链路生成真实向量。

增加一个只使用 Python 标准库的运行器，按固定映射调用现有 multipart 导入接口，再调用批量检索评估接口。运行器允许覆盖本地服务地址，重复执行时沿用现有“来源 + 版本”幂等语义，不自动删除资料。

## 边界

- 不修改固定题目、检索算法、`topK` 或相似度阈值。
- 不增加 Maven/Python 依赖、数据库表、自动启动导入或生产配置。
- 不自动清理已导入的基线语料；这些资料是后续对照实验的稳定输入。
- 本轮只验证来源命中，不调用 Chat 模型，也不实现回答要点评分。

## 验收

- 5 个逻辑来源均能通过现有接口导入或被识别为已导入。
- 批量接口返回 6 道题，6 道题均在 `topK=5` 内命中期望来源。
- 保存本次真实报告，记录模型、参数、时间和各题实际相似度。
