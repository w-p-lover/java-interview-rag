# 面试文件输入设计

## 目标

在 `/interview` 将简历和可选 JD 的 Markdown/TXT 文件选择作为主入口，自动提取正文后继续复用现有 `resumeText` 与 `jobDescription` 请求契约。文件和正文只用于本场面试，不进入知识库、不写向量，也不保存到浏览器本地。

## 方案

- 新增单一职责组件 `InterviewTextFileField`，负责一个文件的类型校验、本地文本读取、字符数校验、状态提示和备用文本编辑。
- 支持 `.md`、`.markdown` 与 `.txt`；PDF/DOCX 继续明确不支持，不展示无法可靠解析的入口。
- 简历正文上限沿用 50000 字符，JD 上限沿用 30000 字符。读取失败、空文件、类型不支持或正文超限时保留原文本并显示中文错误。
- `InterviewSetupForm` 继续只提交字符串 payload，不增加 multipart API、后端临时文件或新的持久化模型。
- 纠正资料库页面中把简历/JD 描述为长期知识资料的旧文案，稳定来源示例改为知识文档语义。

## 交互与状态

文件选择区显示允许格式；读取中禁用重复选择；成功后显示文件名和提取字符数，正文仍可在下方文本框中检查和编辑。简历必填，JD 可选；提交规则仍由原生表单必填约束和后端校验共同保证。

## 验证

- 执行前端类型检查和生产构建。
- 在浏览器中验证 Markdown 简历、TXT JD、错误格式与窄屏布局；不调用真实模型或存储服务。
