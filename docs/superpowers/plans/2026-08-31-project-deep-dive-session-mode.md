# 项目深挖会话接入实施计划

> 日期：2026-08-31
> 目标：将固定四问的项目深挖接入现有面试会话、逐题评分、持久化恢复和最终报告链路。

## 边界

- 新增显式会话模式 `STANDARD` / `PROJECT_DEEP_DIVE`，历史数据默认按标准面试恢复。
- 项目深挖仅使用已确认的项目事实生成固定四问，不调用 Chat 生成题目。
- 复用现有 `InterviewAnswerEvaluator`、答题推进、最终报告和最近会话链路。
- 本轮不执行真实 MySQL 迁移，不调用 Chat、Embedding 或 Qdrant，不新增第二套会话表和评分器。

## 实施步骤

1. 在会话领域模型、服务和 MySQL 映射中加入模式，并新增 `017_interview_session_mode.sql`。
2. 新增项目深挖会话启动服务和控制器入口，将 `ProjectDeepDiveService` 的四问映射为现有 `InterviewQuestion`，题数上限固定为 4。
3. 调整前端 API、组合式函数和面试页组件，支持从项目审计结果直接开始深挖，并在进行中、报告和最近会话中显示模式。
4. 补充直接相关的后端测试，覆盖启动、模式持久化、四问结束后不追加动态追问和控制器契约。
5. 执行聚焦 Maven 测试、前端构建和浏览器 Mock 验收；同步当前进度、开发记录、技术决策、功能总结和后续路线。
6. 检查并仅暂存本闭环文件，执行 `git diff --cached --check` 后提交 `feat: 接入项目深挖会话`。

## 验收标准

- 用户可从已确认项目事实启动一个 `PROJECT_DEEP_DIVE` 会话，且恰好包含四道固定深挖题。
- 每题继续使用现有证据化评分；第四题提交后生成现有结构的最终报告，不产生动态追问。
- 会话模式可写入和恢复，旧数据兼容为 `STANDARD`。
- 前端在桌面和 375px 宽度下可完成启动、答题、报告及最近会话恢复，且无布局溢出和控制台错误。
