### 首个学习单元：项目全貌与知识导入（45–90分钟）

先不用材料回答：“上传一份知识文件后，系统怎样让它成为可检索资料？MySQL、文件存储、Qdrant、Lucene分别保留什么？如果只有一路索引写成功，为什么不能直接给用户成功？”

1. 5–10分钟：本人画组件图与理解中的导入链，保留不确定处。
2. 20–35分钟：阅读项目答辩和上述Controller、任务Service、切分器，继续追到实际Importer/Store与发布条件，修正图中的数据和状态。
3. 10–20分钟：关闭材料，按业务、调用、数据、取舍、失败、证据六维口述；重点解释一个成功和一个失败路径。
4. 10–20分钟：回答五个追问：为什么异步；重复文件如何处理；attempt与generation为什么分开；事务能否回滚三个存储；原文件和索引为何分开管理。

**作答后对照：** 文件输入要可恢复；任务完成与索引发布属于不同事实；版本/索引契约不能只看文本hash；旧执行通过条件写隔离；部分构建未发布时不能污染正式检索。具体字段和顺序须以当前源码为准。这些只是检查点，不代表本人已回答正确。

同一单元没有本人反馈时保持待作答，不每天生成新课程或示范。得到真实反馈后再安排第二单元；可以开始投递，不等待全部模块满级。

## 一、达到什么程度可以开始投递

满足以下要求即可开始投递，不必等待所有后续技术完成：

- 能在 30 秒内讲清用户、主流程和三个工程亮点。
- 能不看文档画出 Vue、Spring Boot、Spring AI、MySQL、Qdrant、Lucene BM25 和 DashScope 的关系。
- 能完整讲清知识导入、RAG 回答、模拟面试、复习 Tool Calling 四条调用链中的至少三条。
- 能解释五个 RAG 指标及当前固定集、DEV/HOLDOUT 划分与语料契约的局限；旧8份/18 Chunk只是历史基线。
- 能说出至少五个真实失败场景及项目的处理方式。
- 能定位 Controller、核心 Service、持久化、模型调用、向量检索和直接测试。
- 能演示一条完整流程，并根据日志区分配置、数据库、Qdrant、模型和业务校验问题。
- 简历只写已实现并验证的能力，未完成内容明确标为 POC 或后续方向。

完成前六项即可开始投递；全部完成后，可以把项目作为 Java AI 应用/RAG 岗位的主讲项目。Graph、MCP、Memory 和多模型路由不是开始投递的前置条件。

## 二、必须掌握的核心内容

当前面试优化不按“把所有 P1 都做完”执行，而按以下顺序掌握和开发：

1. **基础逻辑与失败恢复（最高优先级）**：文档版本、Chunk 元数据、MySQL/Qdrant/Lucene 状态、幂等、补偿、重启恢复和一致性巡检。这些内容最能体现 Java 后端工程能力，必须结合真实代码和失败路径讲清楚。
2. **RAG 质量链路（第二优先级）**：解析/切分、Dense/Sparse/Hybrid 召回、拒答门控、引用合法性和 claim 证据校验。重点是知道每一层解决什么问题，以及指标不能证明什么。
3. **面试训练闭环（第三优先级）**：评分、证据验真、复述卡、复习 attempt、同题再练和项目深挖。重点是能把一次回答转成下一次动作，而不是只展示模型分数。
4. **运行可靠性与容量（有证据再做）**：超时、并发舱壁、索引任务恢复和容量指标。只针对真实瓶颈补齐，不提前引入通用 MQ、Tokenizer 或微服务。
5. **前沿扩展（暂缓）**：用户空间、GraphRAG、MCP、多 Agent 和复杂 rerank；已实现的Provider路由应学习现有契约，第二模型验收仍按条件进入。

### 工程化 RAG 专项追问

必须能够基于当前实现回答以下问题，不把后续方案表述为已经完成：

1. 当前 Redis 回答缓存缓存了什么、如何按知识版本失效？哪些对象仍不适合缓存，为什么拒答、失败和部分回答不进入缓存？
2. 文档导入、重建或删除后，检索缓存如何失效？模型、Prompt、Chunk 策略和权限发生变化时，缓存键还需要包含什么？
3. 知识问答为什么不会随着页面历史无限增大？用户追问“它为什么这样做”时，为什么仍可能检索失败？
4. 当前面试上下文如何限制条数、单条长度和总预算？字符上限与Token预算有什么区别，旧信息被裁剪后如何处理？请核对当前实现参数。
5. 当前Token预算切分如何处理段落、代码和表格续块？JTokkit估算为什么不等于Qwen精确计费Token？
6. 为什么先做切分消融和困难样本，而不是直接引入语义切分、父子索引或 rerank？
7. Markdown 知识资料、PDF 知识资料、PDF 简历、Markdown/TXT 简历分别在哪里解析，最终数据是否进入 MySQL、Qdrant、Lucene 或只进入本场模型上下文？
8. PDF 的双栏、跨页章节、重复页眉页脚、代码和表格怎样识别？复杂双栏表格、图片语义和扫描页当前为什么不能宣称已支持？
9. 多份不同来源文件进入同一知识库后，怎样避免跨文件污染？未来知识空间、来源过滤和权限应该放在哪一层？
10. 模型返回了 `[资料 1]` 是否就能证明回答可信？如何识别不存在的编号、错引、漏引和来源不支持的结论？
11. MySQL 登记成功、Qdrant 写入成功，但 Lucene 写入失败时会留下什么状态？为什么数据库回滚不等于三个存储都回滚？进程重启后如何继续识别这次失败？
12. Embedding 模型、向量维度、Chunk 策略或解析器版本变化时，只有内容哈希为什么不够？旧索引如何识别、重建和回退？
13. 20 多道固定题接近满分为什么不能证明生产质量？怎样设计同名概念、多版本冲突、跨文档和长尾问题？
14. 当前项目为什么不能直接公网开放？知识资料导入、删除、评估和日志接口需要哪些最小身份与权限边界？
15. Qdrant、Embedding 或 Chat 服务失败时如何区分重试、拒答和降级？为什么降级到 Sparse-only 也不能绕过可靠性判断？
16. 当前检索 P95 能证明什么、不能证明什么？如何验证大语料和并发下的瓶颈，而不是只报告单次固定集耗时？
17. 当前 Actuator 和业务指标为什么还不等于完整生产可观测性？Trace、告警、敏感正文和高基数标签如何处理？
18. MySQL、Qdrant 和本地 Lucene 如何备份恢复？多实例部署时本地 Sparse 索引如何避免不一致？
19. 为什么 BM25 只是候选召回的一部分？Dense、Sparse 和 Hybrid 分别解决什么问题，哪类失败三者都解决不了？
20. Recall@5 很高但 Precision@5 较低意味着什么？直接增大 TopK 会怎样影响上下文噪声、延迟和最终回答？
21. Hit@1 和 MRR 都是 `1.0000`，为什么仍不能声称回答准确？从候选、排序、拒答、生成和引用五层分别说明。
22. RRF 为什么能隔离 Dense/BM25 分数尺度，却不能补回两路都未召回的资料，也不能解决语料缺失？
23. Chunk 切分、标题路径、代码/表格块类型和相邻 Chunk 扩展如何同时影响召回率与精确率？什么情况下扩展反而有害？
24. `grounded=true`、返回了来源、出现了 `[资料 1]` 三件事分别能证明什么？为什么都不自动等于 claim 级事实正确？
25. 如何定义引用精确率、引用召回率和无依据陈述率？错引、漏引、引用不存在和资料外补充分别落在哪个指标？
26. 同名概念、多版本冲突、跨文档多证据和纯中文近域无答案应该怎样进入评估集，如何避免针对开发集调到过拟合？
27. 查询拆分真实对照为什么退化？什么证据出现后才值得重新启用多查询，而不是继续增加查询次数？
28. 一次回答错误时，如何通过日志和评估结果定位到语料、解析、切分、候选召回、融合排序、拒答门控或生成引用中的具体一层？

当前合格回答应明确：Redis 回答缓存已实现但仍缺生产命中率、成本和容量证据；知识问答支持当前请求内有限多轮上下文但不保存跨请求长期记忆；面试上下文是有界摘要；简历审计默认总超时为 420 秒且可配置，RAG 回答默认服务端超时为 60 秒；Markdown使用标题、段落/代码/表格结构与统一Token预算切分；知识 PDF 与简历 PDF 复用底层版面分析但采用不同上层生命周期；BM25 只是候选召回的一路；RRF 不能解决语料缺失；`grounded=true` 和返回来源不等于逐结论事实一致；三个存储没有分布式事务；小型固定集和单实例指标不能外推到生产。详细缺口和进入条件见 [问题清单](11-问题清单.md)，开发顺序见 [后续开发路线](09-后续开发路线.md)。

## 三、新 Agent 完成后追加掌握

| 技术 | 需要达到的程度 |
| --- | --- |
| 简历证据审计 | 解释事实、证据、缺失、风险和建议为何分离；会计算事实准确率、证据合法率和虚构率；能演示简历内提示注入不会改变规则 |
| 图工作流 | 说明普通链何时足够、何时需要状态图；画出节点、条件边、有界循环、HITL 和 checkpoint；解释恢复时如何避免重复调用和写入 |
| OpenTelemetry | 解释 span 边界、trace 传播、敏感正文、高基数标签和采样；能定位一次请求在哪个环节失败 |
| MCP | 解释 Resources、Prompts、Tools、Client/Server 和 Transport；说明 MCP 是 Agent 到工具，A2A 是独立 Agent 到 Agent |

图工作流、OpenTelemetry 或 MCP 只有真实代码、运行结果和消费者时才能写“实现并验证”；隔离实验必须写“POC”。

## 四、只需了解适用场景的方向

| 方向 | 投递前至少需要知道 |
| --- | --- |
| 查询拆分与 RRF | 多查询补召回、RRF 融合排序，以及为什么必须与原查询做同口径对照 |
| Hybrid Search | dense 和 sparse 的互补关系、RRF 按排名融合、分数尺度隔离，以及当前真实基线只证明标题路径局部收益 |
| rerank | 主要优化排序，会增加模型、延迟和费用，不能解决语料缺失 |
| Agent Memory | 不等于聊天记录；需要身份、来源、冲突、过期和删除规则 |
| GraphRAG | 面向实体关系和多跳问题，不是向量检索的默认升级 |
| A2A | 面向独立 Agent 系统互操作，不等于进程内子 Agent 或工具调用 |
| Temporal | 面向长任务和持久化执行，不是所有图工作流的必需组件 |
| 多模型路由 | 当前Provider中心与Chat/Embedding路由已实现，必须解释现有契约、活跃任务和索引保护；第二模型质量/费用/延迟对照按资源条件进入 |
| Ragas/Langfuse/Phoenix | 分别偏离线评估或调用链观察，不应为了技术数量全部接入 |

这些方向能解释概念和进入条件即可；没有代码和结果时，不写进简历成果。

## 五、推荐口述结构

### 30 秒版本

```text
这是一个基于 Java、Spring Boot、Spring AI、MySQL 和 Qdrant 的 Java 面试训练系统。
它覆盖知识版本和向量生命周期、RAG 问答、固定评估、简历个性化面试、证据化评分、
复习任务和受控 Tool Calling。模型负责生成和评价，Java 负责状态、幂等、证据验真、
工具授权和数据边界，所以重点不是接模型 API，而是可信 RAG 和 Agent 工程治理。
```

### 3 分钟版本

1. 用户问题：资料查询、个性化面试和复习缺少可信闭环。
2. 系统架构：Vue、Spring Boot、Spring AI、DashScope、MySQL、Qdrant。
3. RAG：版本导入、切分、向量生命周期、阈值拒答和来源引用。
4. 面试：画像、出题、评分、追问、报告和复习 attempt。
5. 治理：固定评估、Java 证据验真、工具白名单、人工确认和无正文日志。
6. 结果与边界：给出真实指标，同时说明语料规模和未实现方向。

### 10 分钟深挖版本

只选两个问题讲深：

- MySQL 登记与 Qdrant 向量的失败恢复和最终一致性。
- RAG 评估如何发现跨主题漏召回，以及查询拆分为什么不直接进入生产。
- 评分引文如何经过 Java 验真，为什么仍不能证明评分长期稳定。
- Tool Calling 如何处理会话越权、人工确认、重试和重复写入。
- 简历证据审计如何处理事实、证据、提示注入和图工作流恢复。

## 六、Codex 开发下的学习方法

每完成一个闭环，不逐行背代码，但必须完成：

1. 自己找到入口 Controller、核心 Service、数据对象、持久化实现和直接测试。
2. 手动画一次调用链或状态图，不直接复制生成的架构图。
3. 不看文档回答“业务问题、方案、取舍、失败、指标、回退”六个问题。
4. 手动运行一次正常演示和一次失败演示，观察日志和返回状态。
5. 先独立口述 Codex 生成的追问题，再让 Codex 指出事实错误和遗漏。
6. 把无法回答的问题列为学习任务，不通过增加技术栈掩盖知识缺口。

评分后新增的回答复述卡用于把一次评价转成下一次训练动作：先看题目目标，再按“结论→原理/实现→边界/取舍”复述，逐项补上遗漏，最后完成口述自检。复述卡是基于当前评分和已验真资料的确定性整理，不是模型生成的标准答案；仍需以自己的项目事实和实际代码为准。

投递前建议约 60% 时间用于系统学习和口述训练，25% 用于核对实现与测试，15% 用于演示、文档和简历调整。代码量不是主要瓶颈，能否解释设计和失败边界才是。
