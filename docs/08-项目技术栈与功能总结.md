# 项目技术栈与功能总结

> 更新时间：2026-08-13
> 代码基线：当前分支已经提交并验证的能力；工作区未提交的本机配置不计入已完成功能。

## 一句话定位

`java-interview-rag` 是一个面向 Java 求职学习者的知识库与智能训练平台，以 Java 17、Spring Boot 3 和 Spring AI 为主线，覆盖资料版本化、RAG 检索问答、文本模拟面试、证据化评分、复习训练和受控 Tool Calling。

## 核心功能

### 1. 版本化知识库

- 支持 Markdown 导入、标题解析、段落优先切片和内容指纹版本判定。
- 以“逻辑来源 + 内容版本”保证重复导入在 Embedding 前短路。
- 支持新版本替换、当前版本重建、来源级淘汰和历史版本元数据查询。
- 将标题层级和 chunk 顺序持久化为无正文目录快照，支持浏览当前版本章节树及旧数据重建提示。
- MySQL、Qdrant 与 Java 统一采用大小写敏感的来源语义，并处理写入失败回滚和旧向量清理。

### 2. 可追溯 RAG

- 通过 Qdrant 相似度检索返回正文、来源、文档版本、chunk 顺序、标题路径和相似度。
- 可靠命中后才调用 ChatModel；资料不足时直接返回兜底，不让模型脱离知识来源回答。
- 提供资料目录、当前版本章节树、标题路径检索草稿、版本详情、原文件重传式当前版本重建、零 Chat 费用语义检索和单次资料问答入口。
- 回答来源可以展开核对，并保留检索参数、Prompt 版本、耗时、状态和失败类型。

### 3. RAG 与模型质量评估

- 固化 20 道六类困难检索题、8 份 Markdown 竞争语料、期望来源与完整标题路径，输出 Hit@1、Recall@5、MRR、标题路径召回和无答案拒答准确率。
- 记录 RAG 召回日志，但不保存知识正文或模型回答。
- 使用 5 类脱敏回答样本评估空回答、无关、部分、完整和无知识来源场景。
- 按 `baselineRunId`、`caseId`、Prompt、rubric 和模型版本比较分数、方差、耗时和失败类型。
- 使用现场生成的单栏、双栏、嵌入中文字体简历、右侧日期列、无边框技能表、复杂侧栏、混合和无文本层 PDF，在同一评估器下比较页数、关键短语、阅读顺序、文档类型和 OCR 候选页；`pdfbox-layout-aware-v2` 为 8/8、文本关键短语 35/35，原 `v1` 的 2/3 和四类 `v2` 报告保留用于回归对照。

### 4. 文本模拟面试

- 支持目标岗位、PDF/Markdown/TXT 简历和可选 JD，自动生成候选人画像与面试关注领域。
- PDF 逐页区分文本、图文、仅图像和空白，保守调整清晰双栏阅读顺序；混合文件保留可用正文并提示用户检查没有文本层的具体页码。
- 基于画像生成首轮问题，并为每题检索真实知识来源。
- 逐题完成技术、完整性、表达和综合评分，必要时追加一条动态追问。
- 会话持久化到 MySQL，通过题号与乐观锁防止延迟或并发重复提交，完成后自动生成报告。
- 回答证据和知识证据由模型提出候选，再由 Java 服务端执行字面包含和来源一致性验真。

### 5. 复习与重复练习

- 根据正式回答中的遗漏确定性生成复习任务，不为生成任务再次调用模型。
- 支持任务状态、计划日期、会话内筛选、幂等完成和多次 attempt。
- 返回正式、首次、最近、最好分数，以及相对正式回答和上次 attempt 的变化。
- 基于持久化事实生成单会话复盘，并确定性推荐下一道仍有遗漏的题目。

### 6. 受控 Tool Calling

- 复习助手只暴露查询任务、读取进展和调整计划日期三个边界明确的工具。
- 顶层 `sessionId` 通过模型不可见的请求上下文绑定，工具不能访问请求之外的会话。
- 改期必须携带与工具参数完全一致的结构化人工确认，模型不能自行猜测或替换标识。
- 请求日志和工具日志记录模型、token、耗时、状态、次数及失败类型，不保存消息、回答、工具参数或知识正文。
- 模型 HTTP 重试与业务写操作分离，避免重试重复执行已经成功的写工具。

## 工程亮点

1. **不是演示型 RAG**：覆盖导入、版本、向量替换、删除、重建、检索、引用、日志和固定评估集的完整生命周期。
2. **评价结果可核验**：回答引文和知识引文都经过服务端验真，评分同时携带 Prompt、rubric、模型和知识来源快照。
3. **模型与业务职责分离**：模型负责生成、评价和工具选择，Java 服务端负责会话状态、权限边界、幂等、验真和持久化。
4. **Agent 能力保持受控**：使用单会话上下文、有限工具、显式写入确认和无正文审计，不扩展为不可控的通用 Agent Runtime。
5. **失败路径可恢复**：向量写入失败撤销版本登记，日志写入失败不影响主流程，评价和工具失败保留明确状态。
6. **数据生命周期清楚**：知识资料长期版本化并向量化；简历和 JD 只用于本场面试，不进入知识库或浏览器长期存储。

## 已验证事实

- 固定 RAG 语料的 6 道题全部首位命中期望来源；该结果只代表当前窄语料基线，不代表任意知识库质量。
- 20 题困难评估已完成真实 `text-embedding-v3` 基线：Hit@1 `1.0000`、Mean Recall@5 `0.9706`、MRR `1.0000`、标题路径召回 `0.9130`、无答案拒答准确率 `1.0000`。结果只代表当前 8 份固定语料和 18 个 chunk；无答案最高候选为 `0.5700`，距离生产阈值只有约 `0.03`。
- 证据化评分 `v3/v2` 完成两轮固定基线，8 次成功模型评价均通过回答证据和知识证据验真，结果保存在 `evaluation/results/2026-08-08-verifiable-interview-answer-baseline.json`。
- 复习进展助手已用脱敏持久化会话验证，能够正确解释 `60 -> 75（+15）`，并区分“尚未练习”和“分数下降”。
- 查询任务、调整计划日期和请求级可观测性均完成真实模型调用验证；验证产生的合成业务数据和日志已按记录清理。
- 仓库包含 13 个按顺序执行的 MySQL 初始化/迁移脚本，覆盖文档版本、会话、复习、评价和工具可观测性。
- DashScope Embedding 按每批最多 10 个 chunk 写入，避免超过当前服务端批量限制。

## 简历可用表述

### 项目描述

基于 Java 17、Spring Boot 3、Spring AI、MySQL 和 Qdrant 独立开发 Java 面试知识库与智能训练平台，完成从资料版本化、RAG 检索问答、模拟面试、证据化评分到复习再练和受控 Tool Calling 的业务闭环。

### 核心职责与成果

- 设计 Markdown 知识资料的版本化向量生命周期，以“来源 + 内容版本”实现幂等导入、新版本替换、当前版本重建和来源级删除，并将标题结构保存为无正文版本快照，处理 MySQL 登记与 Qdrant 写入之间的失败回滚。
- 构建可追溯 RAG 链路，返回来源、版本、标题路径、chunk 顺序和相似度；资料不足时阻止模型自由回答，并建立覆盖排序、来源召回、标题路径与无答案拒答的 20 题评估体系，真实基线 Hit@1 与 MRR 均为 `1.0000`，Mean Recall@5 为 `0.9706`。
- 实现简历/JD 驱动的文本模拟面试，覆盖结构化画像、动态出题、知识检索、逐题评分、追问、持久化会话和最终报告，并使用乐观锁与题号校验防止重复提交。
- 建立证据化评分与可比较基线，模型生成候选引文后由 Java 服务端验真，同时记录 Prompt、rubric、模型、分数、耗时和失败类型；两轮固定基线的 8 次成功评价全部通过证据校验。
- 实现复习任务、多次 attempt、分数变化和单会话复盘，并通过 Spring AI Tool Calling 提供受限查询与改期；写操作要求结构化人工确认，工具和请求日志不保存敏感正文。

### 30 秒口述版本

这个项目不是简单接一个大模型，而是用 Java 完成了一套可验证的 RAG 面试训练系统。知识库部分有 Markdown 解析、版本判定、Qdrant 向量生命周期、来源引用和固定检索评估；业务部分从简历和 JD 生成面试画像与题目，逐题评分、动态追问，再把遗漏沉淀为复习任务。评分引用会由 Java 服务端验真，复习助手的工具调用也有会话隔离、人工确认和审计日志，所以重点体现的是 RAG 质量治理和受控 Agent 工程，而不只是 Prompt 调用。

## 面试展开点

- 如何保证 MySQL 版本登记与 Qdrant 向量写入最终收敛。
- 为什么知识不足时不调用 ChatModel，以及如何验证回答引用。
- 如何区分检索质量、回答质量和评分模型稳定性。
- 为什么正式回答、复习 attempt 和固定基线需要不同的评价模式与关联标识。
- Tool Calling 的会话越权、重复写入、模型重试和人工确认如何处理。
- 为什么当前没有直接引入混合检索、GraphRAG、多 Agent、MCP Server 或 AI Gateway，以及图工作流何时才值得进入正式链路。

## 前沿技术对应关系

| 技术方向 | 当前状态 | 进入项目的门槛 |
| --- | --- | --- |
| 混合检索、RRF、rerank | 暂不引入 | Hit@1/MRR 已为 `1.0000`；先用查询拆分验证唯一跨主题来源漏召回 |
| 上下文化切片、父子索引 | 已具备标题路径、章节树与显式检索入口 | 标题路径召回 `0.9130`，先比较低成本章节扩展再决定是否增加索引结构 |
| PDF 文档理解 | 已有逐页文本/图像分类、双栏重排和 8 类确定性基线；OCR 明确暂缓 | 继续验证经授权脱敏的真实文本层中文简历和复杂字体/表格 |
| Agentic RAG | 已有受控工具基础 | 明确需要多轮查询规划，并能限制次数、成本和工具范围 |
| 角色 Agent 与图工作流 | 规划从简历证据审计官开始 | 先建立普通 Spring AI 基线；真实出现条件分支、修正循环、HITL 或 checkpoint 后再正式引入并对照评估 |
| GraphRAG | 暂缓 | 多文档、多实体、多跳固定样本证明向量 RAG 稳定失败 |
| Agent Memory | 仅有单会话持久化事实 | 建立用户身份、数据归属、冲突、过期和删除规则 |
| MCP | 暂缓 | 出现明确外部客户端或跨应用复用需求 |
| A2A、多 Agent | 不进入当前阶段 | 单 Agent 无法完成且拆分收益能被真实任务验证 |

## 维护规则

- 新增或替换核心技术、模型、数据库、向量库、前端框架时，更新“技术栈”。
- 完成用户可感知的主要业务闭环时，更新“核心功能”和“工程亮点”。
- 产生新的真实评估结果、迁移数量或可量化指标时，更新“已验证事实”和简历成果，注明适用边界。
- 只有已经实现并验证的能力可以进入简历表述；计划项只能写在“前沿技术对应关系”中。
- 小型修复、样式调整、内部重命名和未改变项目能力边界的改动不需要更新本文件。
