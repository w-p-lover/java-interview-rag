# 项目技术栈与功能总结

> 更新时间：2026-09-18
> 代码基线：当前分支已经提交并验证的能力；工作区未提交的本机配置不计入已完成功能。

## 一句话定位

`java-interview-rag` 是一个面向 Java 求职学习者的知识库与智能训练平台，以 Java 17、Spring Boot 3 和 Spring AI 为主线，覆盖资料版本化、RAG 检索问答、文本模拟面试、证据化评分、复习训练和受控 Tool Calling。

## 核心功能

### 1. 版本化知识库

- 支持 Markdown 导入、标题解析、段落优先切片和内容指纹版本判定；围栏代码和标准表格在同一标题章节内分别生成 `CODE`、`TABLE` Chunk，标题路径与内容顺序保持不变，并直接进入 Qdrant 块类型元数据和 Lucene 代码字段。
- 以“逻辑来源 + 内容版本”保证重复导入在 Embedding 前短路。
- 支持新版本替换、当前版本重建、来源级淘汰、历史版本元数据查询，以及具备可信快照版本的人工回退；回退失败会使用原当前快照补偿两类索引、目录和激活状态。
- 新登记同时保存规范化正文、结构化章节和无正文目录快照；历史 PDF 回退保留标题路径、页码和块类型，迁移前无正文快照的旧登记明确不可恢复。
- MySQL、Qdrant、Lucene 与 Java 统一采用大小写敏感的来源语义；新版本写入任一索引失败时按来源和版本补偿两个索引并撤销登记，旧版本清理失败时保留新版本，通过同版本重传幂等收敛且不重复 Embedding；支持按来源巡检当前版本数量、旧版本残留和生成契约，并在人工确认后使用可信快照修复两类索引。
- 知识上传先保存原文件对象，异步任务只持久化 `fileId`；Worker 领取后读取并解析，应用重启时以新 attempt 最多恢复一次，旧 attempt 不能覆盖当前终态。版本详情可下载对应原文件，删除来源后仅清理已无业务引用的对象。

### 2. 可追溯 RAG

- 通过 Qdrant 相似度检索返回正文、来源、文档版本、chunk 顺序、标题路径和相似度；文本型 PDF 可过滤重复页眉页脚，识别章节、正文、列表、代码和表格，检索结果额外保留页码与块类型。
- 可靠命中后才调用 ChatModel；资料不足时直接返回兜底，不让模型脱离知识来源回答。
- 初始可靠命中后按同来源、同版本和相邻 chunk 顺序补充有限上下文，最多处理 3 个种子、返回 8 条资料；裸检索和评估接口保持原始 topK/阈值语义。
- 提供资料目录、当前版本章节树、标题路径检索草稿、版本详情、原文件重传式当前版本重建、零 Chat 费用语义检索和单次资料问答入口。
- 回答来源可以展开核对，并保留检索参数、Prompt 版本、耗时、状态和失败类型。
- 提供 `/api/knowledge/answer/stream` SSE 入口，使用 Spring AI `stream().content()` 增量发送回答；结束事件统一携带可靠资料状态和完整来源，前端无需新增流式客户端依赖。
- 提供 `/actuator/health`、`/actuator/info` 和 `/actuator/metrics` 统一观测入口，覆盖 HTTP、JVM 及 Spring AI Chat/VectorStore 调用指标；不开放环境与配置管理端点，也不采集 Prompt 或知识正文。
- 提供业务观测中心：统一生成 `X-Request-Id`，按稳定业务路由统计请求量、失败率、平均/最大耗时，并通过 `/api/observability/overview` 与 Vue `/observability` 页面直接查看；指标不包含会话 ID、请求正文或模型内容。
- 提供动态模型 Provider 控制台：MySQL 保存 Provider 和 Chat/Embedding 默认值，API Key 使用 AES-256-GCM 加密且只写不读；支持新增、编辑、启停、删除、指定能力探测和乐观锁切换。storage 的 Chat/Embedding 真实业务 Bean 按 `providerId + version` 动态路由，历史记录保存 `providerId/modelName#providerVersion`；活跃长任务阻止默认更新，Embedding 必须与已发布索引的模型名和维度完全一致。2026-09-24 验收中当前 Chat 成功，第二模型因权限失败后按规则停止，未宣称双模型质量通过。

### 3. RAG 与模型质量评估

- 固化 26 道检索题，其中 17 道可回答、9 道应拒答；8 份 Markdown 竞争语料标注期望来源、标题路径、Chunk 正例和 Hard Negative，输出 Hit@1、Recall@5、MRR、nDCG@5、Precision@5、标题路径召回、上下文噪声和无答案拒答准确率。
- `/evaluations` 将固定检索评估升级为持久实验：按 `DEV 20 / HOLDOUT 6` 管理 Dense/Sparse/Hybrid 运行，契约包含数据集、语料 SHA-256、索引版本和 Git 标识；逐样本保存并只恢复未成功项，同契约幂等复用。成功运行可生成同口径差异并由人工保存采用或回退，HOLDOUT 不用于反复调参。
- `/evaluations` 同时提供回答引用与评分稳定性实验：回答固定 5 题保存知识依据/引用指标；评分对 4 个可评分样本各重复 2 次，保存分数序列、稳定样本比例、平均波动和评分 P95，运行中断只补缺失样本/重复，并支持候选护栏与人工采用/回退。
- 使用独立的 3 道合成 PDF 结构题验证代码、表格和跨页正文，评估页码、内容块类型以及来源/标题/页码/块类型联合召回；结构题不进入回答评估，不额外扩大 Chat 费用。
- 检索指标、回答要点和引用事实一致性采用不同口径：当前 `grounded=true` 和来源存在不等于每个结论正确，`normalized-literal-containment-v1` 也不能替代语义正确性或人工复核。
- RAG 生成后增加 Java 确定性 claim 证据门槛：引用编号先验真，再在被引用资料的单句或相邻两句中计算技术锚点覆盖和相关否定短语，区分 `SUPPORTED`、`EVIDENCE_INSUFFICIENT`、`EVIDENCE_CONFLICTING` 与 `CITATION_INVALID`；`rag-answer-v5` 禁止模型输出问题拆解和资料覆盖计划，并允许标准部分拒答。2026-09-04 在 `qwen3.7-max-2026-06-08` 上完成 23 题真实闭环：128 个 claim 中 115 个支持，引用精确率 `0.9055`、引用召回率 `0.0952`、无依据陈述率 `0.1016`、冲突率 `0.0234`，15 题保留可靠或部分可靠回答；相比首版基线，可靠回答增加且三项风险指标下降，但字面召回仍不等价于完整语义正确率。
- 记录 RAG 召回日志，但不保存知识正文或模型回答。
- 使用 5 类脱敏回答样本评估空回答、无关、部分、完整和无知识来源场景。
- 按 `baselineRunId`、`caseId`、Prompt、rubric 和模型版本比较分数、方差、耗时和失败类型。
- 使用现场生成的单栏、双栏、嵌入中文字体简历、轻微错位右侧日期、无边框技能表、复杂侧栏、混合和无文本层 PDF，在同一评估器下比较页数、关键短语、阅读顺序、文档类型和 OCR 候选页；`pdfbox-layout-aware-v3` 为 8/8、文本关键短语 35/35，并通过一份授权真实单页 PDF 的视觉顺序复核，原 `v1/v2` 报告保留用于回归对照。

### 4. 文本模拟面试

- 支持目标岗位、PDF/Markdown/TXT 简历和可选 JD，自动生成候选人画像与面试关注领域。
- PDF 逐页区分文本、图文、仅图像和空白，保守调整清晰双栏阅读顺序；混合文件保留可用正文并提示用户检查没有文本层的具体页码。
- 基于画像生成首轮问题，并为每题检索真实知识来源。
- 首轮问题先进入前端草稿，用户可以查看画像摘要和出题依据，修改题目与考察目标、删除、逐题替换或重新生成；确认后使用草稿直接创建正式会话。相同输入和运行契约在进程内共享进行中计算并短期复用，显式重新生成才绕过；材料或题数变化会使旧草稿失效，人工改写题目会清除旧知识绑定。
- 支持 Java 核心、Spring、数据库、系统设计和 RAG/AI 五类 Skill 以及三档难度；存在简历证据时按约 60% 简历题、40% Skill/方向题并行生成，无简历时全部生成方向题。近期同 Skill 历史题的题面、类型和考察目标进入两路 Prompt，生成后再按 NFKC、大小写、标点和空白规范化排除同场重复及近期原题。每题记录主来源和包括知识命中的辅助来源，确认后的 Skill、难度、题数、来源配额、题目来源、Prompt、模型和组卷策略作为会话配置快照持久化，旧会话恢复为明确的 `LEGACY` 快照。
- 简历分支失败时全量改走方向分支，方向分支失败时保留简历题，两路失败或去重产生缺口时由确定性 Skill 固定题补足，并返回真实不可用来源；单题知识检索失败不丢弃模型题。固定题替换不调用模型，生成题替换只改指定题并重算来源配额；不足 3 题的部分草稿不能创建正式会话。
- 正式草稿确认使用客户端稳定 `requestId`；服务先查询持久化映射，再通过 MySQL 唯一键处理并发创建并恢复同一会话。进程内草稿指纹缓存只承担短期费用优化，不作为正式创建幂等依据。
- 逐题完成技术、完整性、表达和综合评分，必要时追加一条动态追问。
- 会话持久化到 MySQL，通过题号与乐观锁防止延迟或并发重复提交，完成后自动生成报告。
- 支持 `STANDARD` 与 `PROJECT_DEEP_DIVE` 两种显式会话模式；项目深挖从审计确认事实确定性生成四题，复用逐题评分和报告，并以四题上限禁止动态追加。
- 回答证据和知识证据由模型提出候选，再由 Java 服务端执行字面包含和来源一致性验真。
- 正式回答通过 SSE 推送阶段事件；恢复会话时读取不含回答正文的事件时间线，并在前端展示回答接收、评价、下一题和完成状态，事件接口失败时不阻断主会话恢复。

### 4.1 知识库题库与专项面试

- 题库题目绑定知识资料 `source + documentVersion`，保存题面、答案要点、参考答案、Rubric、固定追问、逐字证据、审核状态和使用统计；资料版本变化后题目进入 `STALE`，不能静默进入新面试。
- `/question-bank` 工作台支持选择资料、具体 Skill、难度和题量，异步生成题目；任务使用 `requestId` 幂等和同资料版本活动任务唯一键，逐题证据校验、NFKC 题面去重和部分成功保留。排队任务可原子取消并释放本实例队列槽位，重复取消返回同一结果；运行中拒绝取消且保留已成功题目。执行记录 `attemptId`、Worker、开始时间、最后心跳和恢复次数；失联后最多自动补投一次且只补缺失题量，恢复耗尽进入明确终态，旧 Worker 不能覆盖新 attempt，模型调用仍有独立超时边界。
- 审核后的题目支持人工选题或随机组卷，专项会话保存题库答案/Rubric/证据快照，复用现有评价、报告和复习链路；重复创建请求返回同一会话。
- 2026-09-18 已用授权真实样本完成 1 次资料出题和 3 次回答评价：3/3 题保存并绑定当前版本，三题评分 98/97/100；该样本不代表通用模型准确率，低分复习未因高分样本生成。

### 5. 复习与重复练习

- 根据正式回答中的遗漏确定性生成复习任务，不为生成任务再次调用模型。
- 支持任务状态、计划日期、会话内筛选、幂等完成和多次 attempt；知识复习回答按任务+回答生成稳定幂等键，重复提交复用已保存评分，数据库唯一键防止并发重复落库。
- Vue 统一复习中心聚合浏览器最近面试路径与知识复习路径，支持按日期和来源筛选、深链到具体训练，并可直接完成或调整两类任务的计划日期；操作后重新加载聚合结果，单路失败不影响另一类已加载数据。
- 返回正式、首次、最近、最好分数；每次 attempt 展示技术准确性、完整性、表达清晰度相对正式回答和上次 attempt 的变化，并比较仍出现、未再出现和新增评价项。比较从持久化评价确定性派生，不新增模型调用；规范化文本精确匹配不等价于语义掌握判断。
- 基于持久化事实生成单会话复盘，并确定性推荐下一道仍有遗漏的题目。
- 新增跨会话学习路径首版：聚合最近会话的待复习任务和 attempt，按练习状态、得分、遗漏和计划日期生成 1/3/7 天间隔推荐；不读取回答正文，不调用模型，不引入用户身份或全量历史。
- Vue `/review` 将最近最多 8 场面试的复习路径与知识问答复习路径汇总为统一队列，支持今日/逾期、后续计划和来源类型筛选；双路径独立失败降级，并可深链恢复到具体面试任务或知识训练项，后端模型和间隔算法仍保持隔离。

### 6. 受控 Tool Calling

- 复习助手只暴露查询任务、读取进展和调整计划日期三个边界明确的工具。
- 顶层 `sessionId` 通过模型不可见的请求上下文绑定，工具不能访问请求之外的会话。
- 改期必须携带与工具参数完全一致的结构化人工确认，模型不能自行猜测或替换标识。
- 请求日志和工具日志记录模型、token、耗时、状态、次数及失败类型，不保存消息、回答、工具参数或知识正文。
- 模型 HTTP 重试与业务写操作分离，避免重试重复执行已经成功的写工具。

### 7. 简历证据审计工作流

- 使用普通 Spring AI Structured Output 将简历结果拆为确认事实、信息缺失、风险判断和表达建议，不引入图框架或多 Agent Runtime。
- 确认事实分为教育、任职、项目、技术、职责、时间和结果，每条候选引文必须由 Java 服务端在隔离后的原简历中逐字验证；项目名称、技术事实、个人职责和量化结果具有明确语义边界。
- 强提示注入行在进入模型前被隔离，不能作为事实证据；服务只返回隔离数量，不回显被隔离正文。
- 独立请求日志记录角色、Prompt/模型版本、token、耗时、状态和异常类型，不保存简历或审计正文。
- 十一类固定评估按版本保存 90 条预期原子事实和缺失/风险信号，输出七种事实类型的准确率/召回率、证据合法率、虚构率、结构/审计成功率、容量及 token/耗时；报告不含简历或审计正文。
- 固定付费评估使用持久化运行 ID 和异步状态机；相同数据集、角色、Prompt 与模型契约重复启动返回同一运行，客户端断开或应用重启后可查询并继续，恢复只重试失败或未完成样本，终态报告保留部分失败和聚合指标。
- `/interview` 提供可选内联检查，按事实类型展示逐字证据并分开呈现待补信息、人工核对和修改建议；未绑定版本时结果只保存在页面内存，绑定不可变版本时成功结果可在刷新或应用重启后恢复，失败不覆盖旧成功结果，修改简历后旧审计结果标记为待更新。
- `/resumes` 支持选择同一逻辑简历的两个已审计版本，服务端以规范化精确匹配和同类型文本相似度确定性区分未变、变化、新增和删除事实；比较只消费已确认事实，不触发模型调用，也不把缺失、风险或建议伪装成事实变化。

## 工程亮点

1. **不是演示型 RAG**：覆盖导入、版本、向量替换、删除、重建、检索、引用、日志和固定评估集的完整生命周期。
2. **评价结果可核验**：回答引文和知识引文都经过服务端验真，评分同时携带 Prompt、rubric、模型和知识来源快照。
3. **模型与业务职责分离**：模型负责生成、评价和工具选择，Java 服务端负责会话状态、权限边界、幂等、验真和持久化。
4. **Agent 能力保持受控**：使用单会话上下文、有限工具、显式写入确认和无正文审计，不扩展为不可控的通用 Agent Runtime。
5. **失败路径可恢复**：Qdrant/Lucene 部分写入失败会精确清理本次版本并撤销登记；旧版本清理失败保留新版本和 `FAILED` 状态，同版本重传只重试清理；历史回退先重建两类索引再激活版本，失败不切换当前登记并刷新一致性巡检。
6. **数据生命周期清楚**：知识资料原文件、解析快照和索引长期版本化；简历可由用户显式保存原文件与正文为不可变版本，默认仍只保存版本元数据，正式面试和成功派生分析绑定版本 ID；派生表只保存输入指纹、运行契约和结果，临时简历和 JD 仍不进入知识库或浏览器长期存储。
7. **角色事实由 Java 裁决**：简历审计模型只提出候选事实和证据，服务端决定哪些内容能够进入确认事实，风险与建议不能伪装成事实；当前 Prompt 要求逐段原子抽取并做未触顶完整性自检。

- 在 Qdrant 向量检索之外增加嵌入式 Lucene BM25 稀疏检索，并完成 Dense + BM25 Hybrid Retrieval v1：正文、标题、代码和 Java 标识符拆为字段，权重为 `1.0/2.0/2.5/3.0`；两路各取候选后按稳定 Chunk 身份去重，使用 RRF 融合排名并返回双路命中证据。固定题支持 Chunk 正例与 Hard Negative，评估器输出 Precision@5、nDCG@5、Chunk Recall@5、Hard Negative 避免率、上下文噪声和检索 P95。RAG storage 主链路已接入 Hybrid；Dense/Sparse 使用隔离有界执行器和默认 5 秒截止，任一路失败时自动切换到另一条通道，两路失败时不调用 Chat，并提供当前实例容量、超时和拒绝指标。Sparse 原有可靠拒答门控保持生效。评估器按分数体系隔离拒答策略：Dense/Hybrid 使用余弦阈值，Sparse 使用 `technical_anchor_coverage_v2` 英文锚点覆盖和已确认中文 Hard Negative 短语门控后再按候选存在性拒答，不把 BM25 原始分数与余弦直接比较。2026-09-02 的历史字段化真实复核中，Dense/Sparse/Hybrid 的 Hit@1 均为 `1.0000`、Mean Recall@5 均为 `0.9706`、MRR 均为 `1.0000`；Hybrid nDCG@5 为 `0.9772`，但 Sparse 拒答准确率仍为 `0`，因此不能表述为整体质量全面提升。Embedding 写入已具备提供方 HTTP 截止和批次间中断检查，当前仍未完成真实并发容量验证。
- 索引写入链路新增统一版本契约 `KnowledgeIndexVersionMetadata`，将 Embedding 模型/维度、Chunk 策略、PDF 解析器和索引 Schema 版本同时写入 Qdrant payload 与 Lucene 文档；默认值可通过环境变量覆盖。当前该能力用于新索引的漂移识别，尚未自动重建或回退历史索引，也未新增数据库迁移。

### 30 秒口述版本

这个项目不是简单接一个大模型，而是用 Java 完成了一套可验证的 RAG 面试训练系统。知识库部分有 Markdown 解析、版本判定、Qdrant 向量生命周期、来源引用和固定检索评估；业务部分从简历和 JD 生成面试画像与题目，逐题评分、动态追问，再把遗漏沉淀为复习任务。评分引用会由 Java 服务端验真，复习助手的工具调用也有会话隔离、人工确认和审计日志，所以重点体现的是 RAG 质量治理和受控 Agent 工程，而不只是 Prompt 调用。

## 面试展开点

- 如何保证 MySQL 版本登记与 Qdrant 向量写入最终收敛。
- 为什么知识不足时不调用 ChatModel，以及如何验证回答引用。
- 如何区分检索质量、回答质量和评分模型稳定性。
- 为什么正式回答、复习 attempt 和固定基线需要不同的评价模式与关联标识。
- Tool Calling 的会话越权、重复写入、模型重试和人工确认如何处理。
- 为什么 BM25 只是候选召回的一路；为什么当前保留 Hybrid-RRF 但不宣称全面提升，以及如何区分召回、排序、拒答、生成和引用准确性；为什么暂不引入 GraphRAG、多 Agent、MCP Server 或 AI Gateway，以及图工作流何时才值得进入正式链路。

## 前沿技术对应关系

| 技术方向 | 当前状态 | 进入项目的门槛 |
| --- | --- | --- |
| 混合检索、RRF、rerank | Hybrid-RRF v1、字段化 BM25、Chunk/Hard Negative 评估和独立 Sparse 拒答策略已接入；rerank 暂不引入 | 新字段权重需在真实固定题集上比较来源、拒答、Precision/nDCG、噪声和 P95；无稳定收益不增加 rerank |
| 上下文化切片、父子索引 | 已完成 Token-aware 结构切分和统一 Prompt 预算；相邻 Chunk 扩展因噪声上升关闭默认生产路径，当前保持零 overlap | 只有固定失败样本证明边界漏召回时引入有限 overlap；只有子块正确命中但回答因父上下文缺失而失败时评估父子索引 |
| PDF 文档理解 | 已有逐页文本/图像分类、双栏重排；知识资料支持标题、正文、列表、代码、表格和跨页章节识别；`pdf-knowledge-parser-v6` 已用 Oracle JLS、DaCapo、JVMS 分别修复内联等宽文本、窄栏沟/跨栏标题、带表题跨页多行表格，`markdown-section-chunker-v5` 按 Token 切分并为长表格续块保留列头 | 当前证据不支持增加块类型权重或章节聚合；无明确表题的续表、合并单元格、图片语义和其他未覆盖混排仍需真实失败样本，OCR 明确暂缓 |
| Agentic RAG | 已有受控工具基础 | 明确需要多轮查询规划，并能限制次数、成本和工具范围 |
| 角色 Agent 与图工作流 | 简历证据审计官、岗位匹配顾问和确定性项目深挖训练闭环已接入；深挖固定四维、复用持久化评分报告，知识检索显式只读，不调用 Chat 出题 | 真实出现修正循环、HITL 或 checkpoint 后再正式引入图工作流 |
| GraphRAG | 暂缓 | 多文档、多实体、多跳固定样本证明向量 RAG 稳定失败 |
| Agent Memory | 仅有单会话持久化事实 | 建立用户身份、数据归属、冲突、过期和删除规则 |
| MCP | 暂缓 | 出现明确外部客户端或跨应用复用需求 |
| A2A、多 Agent | 不进入当前阶段 | 单 Agent 无法完成且拆分收益能被真实任务验证 |
