## 2026-07-19：Markdown ATX 标题解析

- 目标：把 Markdown 文档转换为后续 chunk 切分可直接使用的有序 section，并保留来源与标题层级。
- 决策：不引入完整 Markdown AST 依赖，先使用逐行扫描支持 1 到 6 级 ATX 标题；扫描器跟踪反引号和波浪线围栏，避免代码示例中的 `#` 被误判为标题。
- 修改：新增不可变 `MarkdownSection` 和 `MarkdownHeadingParser`，保存来源、从 0 开始的顺序、标题级别、标题路径和正文；正文只裁剪 section 边界空行，内部段落顺序保持不变。
- 测试：先确认解析器测试因缺少两个新类型而编译失败，再补最小实现；最终针对性执行标题解析、文档模型与 Spring Boot 上下文测试，共 9 个测试通过，0 失败、0 错误。
- 边界：未实现 Setext 标题、文件导入、持久化、重复导入判定和按最大长度切分，也未新增 Maven 依赖。
- 下一步：基于 `MarkdownSection` 实现按段落和最大长度切分，并保留来源、标题路径与 chunk 顺序。

## 2026-07-20：Markdown 段落与最大长度切分

- 目标：把有序 `MarkdownSection` 转换为后续向量化可使用的 chunk，并保留来源、标题路径和顺序信息。
- 决策：第一版按 Java 字符长度控制上限；优先合并完整段落，加入段落分隔后超过上限时新建 chunk，单个段落本身过长时严格定长切分；不提前增加 overlap 或 tokenizer。
- 修改：新增不可变 `MarkdownChunk` 和无状态 `MarkdownSectionChunker`，chunk 保存全局顺序、原 section 顺序、标题级别和标题路径；空正文 section 不生成 chunk。
- 测试：先确认测试因缺少 `MarkdownChunk` 和 `MarkdownSectionChunker` 编译失败，再补最小实现；最终针对性执行 chunk 切分、标题解析和文档模型测试，共 12 个测试通过，0 失败、0 错误。
- 边界：未实现 overlap、token 级预算、文件导入、导入登记、持久化和向量化，也未新增 Maven 依赖。
- 下一步：实现最小导入登记与“来源 + 版本”重复判定，继续保持阶段 1 的可验证小闭环。

## 2026-07-21：Markdown 文件导入编排

- 目标：把现有文档模型、重复判定、标题解析和 chunk 切分串成可直接调用的 UTF-8 单文件导入入口。
