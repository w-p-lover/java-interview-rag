# 项目掌握与面试学习任务

> 2026-10-13 起，用户明确将主线调整为学习掌握现有项目及相关知识。本任务替代旧的每日自主开发、持续扩课和代理训练要求。

目标定位：Java 后端开发工程师，具备 Spring AI、RAG 和大模型应用工程经验。核心任务是帮助用户理解已有代码、独立解释设计与失败边界，并能面对面试追问。已有功能和课程足够支撑当前学习，不把继续建设系统当作学习完成。

## 每轮开始

1. 读取 AGENTS.md、docs/04-当前进度.md、docs/10-面试准备与项目掌握要求.md 的学习队列和本人证据表。
2. 查看上轮任务之后可取得的用户回答、源码讲解和练习反馈；区分本人回答、代理示范和仅备好材料。旧自动化记录只用于追溯，不能恢复旧开发优先级。
3. 准备修改文件前检查 git status 和差异。围绕一个主题读取真实入口、核心 Service、数据/状态与必要配置，不反复通读整个仓库或全量扫描对话。
4. 开发进入条件及遗留查 docs/09、docs/11；事实冲突以当前源码和最新运行证据为准，不背旧文档的参数、版本或规模。

## 选题与节奏

- 第一轮从项目全貌与知识导入链开始，先检查用户能否画出组件关系和讲清数据去向，再补 Java/Spring/MySQL 基础。
- 后续优先级：用户最新真实错误/追问 -> 当前链未掌握处 -> 已有后端题单 Q3/Q4/Q5/Q7/Q8 -> 其他核心链与基础。
- 主线顺序：项目全貌与知识导入 -> 异步恢复/索引发布 -> RAG 检索与可信回答 -> 面试评分/复习 -> 缓存/工具/Provider/文件存储 -> JVM/运行排查与其他项目答辩。
- 每轮只设一个 45–90 分钟的本人学习单元，包含一个核心概念、一段真实调用链、一个失败场景和 3–5 个追问。优先已有课程，不机械新增、重新导入或批量生成题目。
- 有本人反馈时按具体错误修正讲解、安排同题复述并记录证据；没有本人反馈时不得认定完成、提高等级、模拟本人回答或擅自切换大量新主题。
- 当前单元未作答且材料未变时，仅明确一次“待本人作答”和下一动作。后续保持安静，不每天重复整套材料、评分、运行服务或付费。收到本人反馈后继续。

## 每个学习单元

1. 先给一道诊断问题，让用户不用资料讲清理解；缺少回答记为待作答，不猜测水平。
2. 给出 2–4 个真实源码入口，说明业务问题、请求、调用、数据变化、取舍、失败恢复和证据边界。源码导读与训练单元可以独立成为成果，不要求新增业务代码、数据库记录或向量。
3. 链接已有课程并串联基础；必要时提供一个最小手工实验或调试动作。只有本人执行或回答的证据才能记为完成，自动跑通只证明实验或流程可用。
4. 先呈现闭卷练习和追问，再在明确标为“作答后对照”的部分放参考思路，不用代理高分替代本人训练。
5. 在 docs/10 同一本人证据表维护主题、状态、真实反馈、薄弱点和下一动作。无新反馈不重复写日期或生成日报。L1 认识功能，L2 讲通正常链，L3 解释失败/并发/取舍，L4 独立定位修改并验证。

## 保留开发的进入条件

只保留三类开发：本人实际学习/演示路径被故障阻塞且没有合理绕过；真实数据正确性、隐私/权限、重复计费或恢复缺陷；本人练习暴露具体缺口，需要一个有边界的调试/代码/实验任务。

进入前明确证据、对学习的影响、绕过方式、预期行为和收口条件。可通过阅读原文、现有 SSE 或离线讲解继续时，优先继续学习。JRAG-008 同步生成时延仍未关闭，只有实际阻塞或新的可验证调用方案出现时有限修复；不扩大超时、放松证据或重复同候选付费追分。

暂缓新课程批量吸收、新题库/代理会话、语音/日程扩展、第二模型/S3 验收、GraphRAG/MCP/多 Agent 和无实际需求的容量治理。已有路线保留为条件型储备。

## 操作与验证边界

- 项目写入只发生在当前 java-interview-rag 仓库；blog-springboot、PDM 和既有八股文档只读参考，保护已有改动。
- 不代答正式会话 4a0bfddf-7842-4611-bd8f-486181c3ffe5 或本人复习任务，不伪造掌握证据。该会话状态以实际读取为准，不永远写死零作答。
- 学习讲解默认不调用付费模型、不写业务库、不重启服务。既有必要付费验收和开发库 SQL 授权仍有效，但仅在满足上述开发条件时使用；不新增逐轮确认流程。
- 确需开发时固定最小样本、调用上限和失败后的采用/回退动作，执行直接相关 SQL 与验证；无改变的旧候选不重跑。
- 文档只查差异、链接和事实；代码只跑相关最小测试或编译，不做无关全量测试、依赖/JAR 检查或环境巡检。
- 使用 codex/ 分支，可提交直接相关且验证过的变更；纯学习轮不要求每天提交。不得擅自合并、创建 PR、部署、改生产或强制推送。
